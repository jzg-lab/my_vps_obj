## 2. 目标与成功标准

### 2.1 从使用者的问题出发

- 客户：我有哪些服务，哪份可以使用，剩余多少，何时到期，如何连接，出问题怎么办。
- 管理员从客户出发：这个账号拥有哪些服务，为什么不能用，涉及哪些资源，下一步如何处理。
- 管理员从节点出发：这个节点是否正常，提供哪些线路，关联哪些服务和客户，故障影响多大。

“统一”需要同时满足入口一致、业务记录一致、对象可互相追溯、操作能跟踪到结果。只增加外部链接、嵌入另一套后台、换导航名称或展示几个统计卡片，均不能视为整合完成。

### 2.2 交付目标

1. 管理员从正常网站进入管理控制台，使用已有账号与权限，不再为日常运营维护第二套业务登录。
2. 客户与节点之间通过服务、连接身份、授权组和线路建立可查询关系，支持双向追溯。
3. 开通、续期、暂停、恢复、交付重试、出口分配及常见故障处理在本项目内完成。
4. 节点接入、验证、线路与组配置、套餐使用这些资源形成完整流程。
5. 指标能解释对象、口径、时间与数据覆盖，并能进入对应详情或筛选结果。
6. 高级维护可以保留外部面板；日常业务流程不能依赖管理员在两个面板手工比对和修改权益。

客户网站继续保持现有简洁风格和“我的套餐”入口。此次整合不把基础设施管理塞进普通客户页面，也不更改每份服务独立订阅和独立消费的规则。

## 3. 范围与现有基础

### 3.1 本轮范围

本轮包括统一入口、客户与服务管理、节点与资源管理、运营指标、交付与故障处理、必要的节点接入引导。三批工作共同构成完整交付，第一批只读可见不等于整合结束。

低频原始协议、复杂路由和底层配置编辑保留高级维护入口。除非用户另行明确扩大范围，不建设完整的 Remnawave 替代品，不迁移技术栈或合并两个系统的数据库，不重写代理内核。

**2026-10-24 补充授权：** 为满足不同服务的连接隔离，允许对 Node／Xray 做按服务身份精准终止连接的最小执行层适配，先在隔离环境验证，再决定接入。必须同时证明目标身份旧连接终止、保留配置的新连接拒绝，以及同源 IP 下另一份有效服务的既有连接继续；不得通过关闭断流、共享 IP 白名单或放宽验收代替修复。保留版本固定、可复现构建、并发与协议回归和回退安排；本授权不扩大为整体内核重写、生产部署或每服务独立实例改造。

在线支付、自有 App、自动采购服务器或 IP、通用 SSH 运维平台、多面板管理平台、完整访问行为分析不属于这次整合。只采集管理和故障定位所必需的数据；不以专业指标为由新增客户访问域名或内容监控。

## 4. 入口、导航与页面职责

### 4.1 用户与管理员视角

沿用现有登录、管理员权限和界面框架。管理员在网站侧栏获得“管理控制台”入口，进入后能返回用户视角；切换视角不是另建账号，也不是模拟其他客户登录。

页面和接口均校验权限。普通用户直接输入管理地址、调用管理接口或替换服务标识，也不得读取其他用户数据、节点管理信息或执行管理操作。管理员角色撤销与会话失效后，不得继续依赖前端缓存获得管理能力。

### 4.2 导航组织

| 分组 | 页面 | 主要职责 |
| --- | --- | --- |
| 总览 | 运行概览 | 汇总客户与服务、节点状态、资源库存、异常和待处理项。 |
| 客户与服务 | 客户、已开通服务、套餐模板 | 找到客户，管理指定服务，配置可开通的产品。 |
| 节点与资源 | 节点、节点组与线路、专用出口 | 查看运行情况、组织连接资源、分配与回收出口。 |
| 运行与故障 | 异常任务、操作记录 | 定位交付、用量、权限和撤销异常，跟踪处理结果。 |
| 系统 | 连接配置、网站设置、高级维护 | 管理已有对接配置和网站设置，提供受控的低频维护入口。 |

分组可折叠。优先复用已有页面、路由和组件，名称可按本地化规范细化。既有客服、教程、语言与其他仍在使用的功能应保留可发现的入口，可以作为适当分组中的次级页面；不得因重排导航而删除现有数据或兼容能力。

### 4.3 客户与服务

- **客户列表：**按账号信息搜索，显示独立服务数量、业务异常摘要和明确口径的活跃信息。一个账号只有一条客户记录。
- **客户详情：**列出全部服务；逐份显示权益、用量、交付与同步情况，可进入相关资源。账号封禁和单份服务暂停必须区分影响范围。
- **全局服务列表：**跨客户筛选待交付、即将到期、耗尽、暂停、已撤销、同步异常等服务。搜索、分页、排序和筛选使用服务端实际结果，统计不能取当前页条数。
- **服务详情：**显示条款快照、当前额度、周期、已确认用量、有效期、订阅交付、连接身份、有效授权资源和操作记录。订阅凭据按现有权限保护，不进入日志或普通列表。
- **套餐模板：**定义未来开通的条款与资源条件；已确认的模板额度统一调整规则继续执行，其他历史条款不得被静默覆盖。

### 4.4 节点与资源

节点列表至少包含名称、资源标识、地区信息（有依据时）、接入状态、运行状态、所属组、在线连接、选定时间范围的流量和最后更新时间。缺失地区或指标显示未提供，不根据名称推断并写成事实。

节点详情包含运行信息、线路与组、潜在受影响服务和客户、可取得的当前连接信息、异常与操作记录。客户、服务与节点都应支持互相进入相关详情，并保留返回时的查询条件。

“有权限使用该节点”与“当前观测到在该节点连接”分别展示。前者是潜在影响范围，后者是带时间戳的观测，不能把授权客户全部称为在线客户或已受故障影响客户。

“节点组与线路”负责组成员、客户端可见连接入口及套餐关联。Node、Host、授权组分别保留真实技术含义与稳定标识；不能按显示名称或地区合并对象，不能假定一个 Host 与一个 Node 永远一一对应。

专用出口页保留库存、核验证据、占用服务、待回收状态及历史。到期先保留绑定，确认停用后由管理员回收；没有实际独享证据的资源不能显示为已验证的独享出口。

### 4.5 运行概览与异常页

概览优先回答“今天需要处理什么”：服务交付失败、节点失联、用量待核对、停用未确认、出口待分配或回收。关键数字可进入使用同一口径的列表；图表与列表时间范围、过滤条件必须一致。

异常任务展示关联对象、首次与最近发生时间、最近成功时间、当前阶段、脱敏原因和可执行下一步。相同故障重复尝试应关联到同一操作或事件，不把每次轮询堆成独立待办。

操作记录区别人工与自动操作，保存操作者、对象、变更前后内容或必要摘要、时间和结果。已有“服务历史”中的删除账号归档继续保留，不应仅改名就声称具有完整审计能力。

## 5. 指标定义与数据可信度

### 5.1 指标字典

| 编号 | 指标 | 口径与来源 | 不得混淆的内容 |
| --- | --- | --- | --- |
| M01 | 客户数 | 本项目业务账号去重；筛选条件与列表一致。 | 面板身份数不是客户数，脱离账号的归档服务不是新客户。 |
| M02 | 服务数量与状态 | 本项目服务记录；权益有效、已交付可用、异常分别统计。 | 有效期未到不等于已完成交付；不同异常集合可能重叠。 |
| M03 | 节点状态 | 节点清单结合状态和采样时间，区分在线、离线、未知、未纳管。 | 流量排行榜长度不是在线节点数，接口失败不是全部离线。 |
| M04 | 在线连接或身份 | 采用已验证的远端字段语义，显示统计对象与时间。 | 同一身份跨节点可能重复；不能直接标为在线客户或设备数。 |
| M05 | 服务用量 | 使用已有服务计量与核对记录，上传加下载业务载荷。 | 不从新建图表再次计算权益，不将不同服务余额合成可互用余额。 |
| M06 | 节点流量 | 远端提供的指定范围或累计计数，单位、方向和窗口明确。 | 节点量不自动等于计费量或厂商账单；累计量不是当前速率。 |
| M07 | 同步与交付健康 | 现有任务的待处理、失败、待核对数量，最早等待时间与最近成功时间。 | 队列非空不一定是故障；业务记录成功不代表远端执行成功。 |
| M08 | 出口库存 | 按库存状态和真实服务绑定计算空闲、占用、待核验、待回收。 | 过期占用不能计为空闲，未核验不能计为可交付。 |
| M09 | 即将到期或额度告警 | 依据服务有效期、已确认用量和明确展示的筛选阈值。 | 统计窗口不改变服务权益；阈值需明确配置来源。 |
| M10 | CPU、内存与速率 | 仅在验证远端字段或采集器后提供，注明具体机器和测量时间。 | 面板主机负载不能标成所有节点负载；缺失值不能补零。 |
| M11 | 连通性、延迟与丢包 | 记录探测位置、目标、方法、时间和样本范围。 | 管理接口在线不证明代理通路可用，单点探测不能代表所有客户网络。 |

M01～M08 是基础展示范围；M09 的具体窗口与告警行为在实施时明确；M10～M11 按验证能力逐步接入。某来源不支持指标时，展示能力缺失和原因，登记补齐任务，不以模拟数据交付。未经范围变更，不把全部深度指标或监控平台作为首批前置条件。

### 5.2 每个指标必须附带的语义

实现时为指标明确：对象与单位、来源及范围、采样或业务时间、成功更新时间、完整性、刷新方式和可用状态。已知为零、未提供、不支持、失败、过期和部分数据必须能区分。

服务额度周期继续按北京时间执行；节点今日／7 日／30 日统计使用 UTC 日历日，两者不能混为一套周期。页面展示的时区与时间窗口明确。不同来源不是同一时刻的快照时应如实提示，不制造精确到秒的一致性。失败可保留最后成功数据，但必须同时展示过期或失败状态。

趋势图需要真实历史样本。没有采集前历史时明确起始日期；缺失段保留缺口，不用零补线。跨节点汇总需核实方向、去重和时间对齐，不能为了画曲线重复累加同一业务流量。

刷新、缓存时长、历史保留和探测频率按已有能力与容量测量确定，不承诺实时。页面读取应复用服务端聚合与缓存，避免每个卡片分别遍历全部身份、节点或触发写入。

## 6. 必须贯通的日常流程

### F01：为客户开通独立服务

1. 从客户详情或全局服务列表选择账号与套餐。
2. 检查资源类型、有效授权组、可交付线路；专用出口另检查库存、核验证据和占用。
3. 展示条款与资源摘要后提交，沿用已有幂等开通和资源占用机制。
4. 页面显示当前交付阶段及远端核对结果，可离开再回来继续查看。
5. 达到既有交付条件后提供该服务自己的订阅入口；失败则显示原因与允许的重试操作。

资源检查不是永久保证，提交时仍须防止并发重复占用。请求超时先核对已执行状态，不能直接新建第二份服务或重复发放额度。

### F02：排查客户无法连接

从客户进入指定服务，依次查看账号限制、服务权益、额度与到期、交付状态、同步状态、有效线路和关联节点。展示已确认事实、未知项与相应操作，避免将所有故障统一解释为节点离线。

排障页能区分账号封禁、服务暂停、耗尽、到期、资源未就绪、远端异常和需要客户端侧验证的情况。未知原因保持未知；没有实际探测证据不得显示“连接正常”。不得通过重建身份、重置用量或挪用另一份服务来掩盖问题。

### F03：从节点故障定位影响范围

节点异常 → 查看观测时间与来源 → 列出授权关联的潜在受影响服务 → 按客户去重展示潜在影响人数 → 单独显示有依据的当前连接 → 进入服务排查和恢复核对。

同一客户多份服务不能在人数中重复统计；只有部分线路受影响时不能把整个账号标为停用。页面提供已知可用线路的信息，但不自动改变授权、不切换消费另一份服务，也不自动替换专用出口。

### F04：续期、暂停、恢复与撤销

在指定服务详情发起，先显示单份服务或账号级操作的影响范围，再执行现有生命周期逻辑。分别跟踪业务状态、远端目标状态与已观测状态；收到请求不能直接显示连接已撤销。

续期不重置用量或月度锚点，恢复不能绕过封禁、到期或撤销。部分失败和响应丢失保留可恢复状态。重新执行先检查最新业务条件和远端结果，不重放已完成的权益变更。

### F05：分配与回收专用出口

选择已核验且空闲的资源 → 绑定目标服务 → 验证实际交付 → 展示所属客户和服务。到期或撤销后保持占用，确认连接停用并由管理员回收，再允许分配给下一位客户。

固定、独享和实际出口地址分别需要证据。库存记录成功、连接配置下发成功或管理面板显示 IP，均不能替代实际出口核验。

### F06：接入节点并提供给套餐使用

前置条件：Panel 中已有可用的配置档案（Profile）及入站；缺少时先通过高级维护准备，再回到接入向导选择。向导不代替原始协议配置编辑。

1. 从节点页选择登记已部署 Node，或获取与当前受支持版本匹配的部署配置和安装引导。
2. 记录稳定身份、服务器地址等必要配置，敏感配置只按权限处理。
3. 核对 Node 接入、管理连接、配置与线路状态，分别显示已登记、已连接和待验证。
4. 配置客户端可见线路与授权组，检查组与套餐之间的实际关系。
5. 使用隔离测试服务验证订阅内容、实际连接、计量和权限范围。
6. 记录验证证据后，按明确的资源授权范围供套餐使用。

网页登记不等于服务器安装；接入向导不默认获得远程执行或重装权限。现有 3x-ui 节点接入须另行核查与安排，不能直接视为已部署的 Remnawave Node。

### F07：修改共享资源与常用节点操作

组成员、线路和节点配置修改前，展示将改变的对象、潜在影响服务和客户、是否可能影响现有连接，以及可行的恢复办法。执行前重新检查目标版本或状态；预览后资源已变更时重新核对，避免按过期预览执行。

常用节点操作先验证现有版本 API、权限、执行结果与失败恢复，再开放相应按钮；不支持的操作清楚说明原因。默认不提供无目标范围的一键重启或批量删除。

模板资源范围快照不代表共享组成员永远不变。用户于 2026-10-24 确认：允许共享组／线路修改影响已有服务，执行前必须展示潜在影响客户和服务清单，由管理员明确确认。提交时重新核对资源与影响范围，变化后重新预览；记录原值、结果和恢复办法。客户通知方式仍未确定，不自动向客户发送消息。

同日确认专用出口故障采用人工处理：保留异常与原绑定，管理员核验替代出口并确认后才能更换，不自动切换到共享出口。更换须复用资源占用、停用核对和回收约束；不能先释放尚未确认停用的原资源，也不能把网页登记当成实际出口核验。不借更换修改原服务价格、用量或有效期；费用调整与通知规则另行确定。

**更换确认同时申请恢复（2026-10-24 已确认）：** 不再要求另一次恢复确认。执行时重新检查账号封禁、服务主动暂停、到期、额度及计量／交付前提，只有原有权益允许才恢复；更换本身不得取消主动暂停或绕过任何限制。资源切换成功、恢复申请与实际恢复结果分别记录和展示；受限、失败或结果未知不能显示可用。旧资源仍遵循停用核验与人工回收，不因恢复申请自动释放。

## 7. 状态、权限与失败处理

### 7.1 分开呈现三类状态

| 状态层 | 要回答的问题 | 示例 |
| --- | --- | --- |
| 业务权益 | 这份服务是否应该被允许使用？ | 有效、暂停、耗尽、到期、撤销；沿用现有业务枚举。 |
| 执行与同步 | 最近的操作进行到了哪一步？ | 已提交、执行中、待核对、失败、已核对完成。 |
| 实际观测 | 远端或探测现在提供了什么证据？ | Node 可达、身份已停用、连接验证通过、数据过期。 |

这些是页面语义，不要求不经评估就新增同名数据库状态机。复用已有状态和任务，只有表达真实缺口时才扩展模型。业务允许且配置已交付，也不代表客户当前网络必然可达。

### 7.2 权限与操作保护

沿用现有管理员权限，不为少量管理员预建复杂角色平台。查询与写入在后端授权；复用会话和 CSRF 防护，外部面板 API 密钥不发给浏览器。

资源重分配、批量授权、节点停用等可能影响他人的操作必须显示目标和影响，并有适当确认。查看状态和普通刷新不增加无意义确认。危险操作的可用性来自服务端能力与当前状态，不能仅用前端按钮禁用保证。

高级维护入口明确跳转目的地和用途，采用已有认证方式；不把管理员凭据写入 URL，也不默认承诺免登录。普通客户看不到该入口。

### 7.3 故障恢复与记录

复用既有任务与同步机制，写操作需要可识别的操作记录及幂等或等价的去重保证。网络超时可能意味着结果未知，应先读取核对；局部成功不能全部标为失败后盲目重做。

恢复操作以最新业务规则和资源归属为准，不通过清零、重复开通或伪造完成状态解除异常。操作记录应能够说明人工处理依据，错误信息脱敏，日志不记录密钥、完整订阅或不必要的个人信息。

## 8. 技术集成边界

### 8.1 数据责任

| 数据或动作 | 主要责任方 | 本项目的整合方式 |
| --- | --- | --- |
| 账号、模板、服务权益、周期与已确认用量 | 本项目业务模型 | 复用现有查询和生命周期服务，所有页面读取一致记录。 |
| 专用出口库存、分配与回收记录 | 本项目资源模型 | 与真实核验证据关联，保留占用及恢复约束。 |
| 节点、线路、远端组成员与运行观测 | 已接入的 Remnawave 与节点 | 经现有服务端适配层读取和执行受支持操作，不直接改面板数据库。 |
| 服务到远端身份及资源的关联 | 本项目明确映射 | 使用稳定标识关联，不以姓名、邮箱、节点显示名猜测。 |
| 执行进度、同步差异与审计 | 现有任务机制及必要扩展 | 统一呈现提交、核对和异常，避免新增互相覆盖的 worker。 |
| 实际连接质量 | 经验证的探测或测试 | 与管理连接状态分开，注明范围与局限。 |

浏览器 → 本项目 API → 现有业务服务与 Remnawave 适配层 → 节点系统。实际代理流量继续经过节点，不改由网站业务接口转发。

### 8.2 最小完整实现

- 保持现有 Svelte、后端、数据库与 worker 组织方式；不为整合新增客户、指标、节点微服务。
- 按当前锁定版本验证接口与字段，复用已有兼容能力；不能为获得某个指标擅自升级线上面板。
- 首批通过现有记录聚合实现查询；只有确认必须保存历史、映射或执行记录时才增加存储。
- 复用实体跳转、列表、工具栏、分页、状态与对话框；新增变体先扩展共享组件。
- 新契约和迁移遵循 CONTRIBUTING.md；不得绕开类型、生成器、迁移和语言门禁。

### 8.3 外部维护造成的差异

本项目作为权益操作入口。高级面板发生变更后，应通过现有同步或核对能力识别差异，展示业务目标与远端观测。无法确认归属的资源保留未关联状态，不自动认领或批量覆盖。

已有权益规则明确约定的同步继续执行；新出现的冲突类型、节点级自动修复或覆盖策略须先确认语义。高级维护不能成为新增一套人工权益账的理由。

## 9. 交互与客户体验要求

沿用现有风格，页面以清晰列表和对象详情为主；概览突出可处理事项，不做大面积装饰或重复卡片。中文路径完整提供中文，新增文本同步英俄基础语言。

桌面和手机都应能完成搜索、筛选、查看异常、打开菜单及确认操作。表格允许合理横向查看，但页面整体不得溢出；关键信息和危险操作不能只靠悬停才能发现。状态同时有文字含义，不能只靠颜色。

保留旧入口的兼容行为或明确跳转；详情和筛选页刷新、返回后应能继续定位。无数据、无资源、无权限、加载中、部分数据、接口失败均有明确状态。空列表不能暗示服务正常。

普通客户只看到自己的业务状态、使用说明和必要的故障提示，不暴露内部栈信息、管理凭据或其他客户。管理员的深度指标不应改变用户首页已确认的简洁布局。

## 11. 验收清单

下列场景是管理台专项验收，同时仍须满足需求基线中的多服务、计量和生命周期验收。模拟、数据库联调、真实节点、真实客户端和生产试测证据分别登记。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| UA-01 | 管理员从正常网站进入管理台并返回。 | 同一账号，入口清晰，直接刷新及返回可用；普通客户路径保持简洁。 |
| UA-02 | 普通用户调用管理 API、替换对象标识；管理员权限撤销。 | 服务端拒绝未授权访问；不能从缓存或直接 URL 获得管理能力。 |
| UA-03 | 同一客户拥有多份服务，包含相同模板的重复开通。 | 客户计数一次，服务逐份展示，权益、订阅与用量不合并。 |
| UA-04 | 从客户查节点，再从节点查潜在影响客户。 | 关联可追溯、返回保留筛选；授权关系与当前连接明确区分。 |
| UA-05 | 面板身份或连接数量大于客户数。 | 展示正确名称与口径，不将跨节点连接累加成去重客户数。 |
| UA-06 | 节点清单、流量排行和状态返回不同集合。 | 在线节点来自清单及有效状态，排行长度不充当节点数。 |
| UA-07 | 统计失败、来源不支持、部分数据或超时。 | 与真实零值区分；保留最后成功时间，未知不显示正常。 |
| UA-08 | 切换指标时间窗口、筛选与分页。 | 卡片、图表和明细口径一致；历史缺口不补零，总数非当前页大小。 |
| UA-09 | 开通时资源不足、并发占用、响应丢失后重试。 | 不重复占用、建服务或发额度；核对完成前不声称可交付。 |
| UA-10 | 续期、暂停、恢复、封禁与到期发生竞争。 | 仍遵循现有权益规则；单服务操作不影响另一份有效服务。 |
| UA-11 | 远端写入成功但本地提交或响应失败。 | 显示可核对状态，重试不重放已完成权益；有可追溯结果。 |
| UA-12 | 账号或服务停用后客户端保留旧配置与连接。 | 使用真实节点证据验证执行；仅隐藏订阅或接口成功不算通过。 |
| UA-13 | 从故障客户或离线节点排障。 | 能看到关联状态、已知原因和下一步；未知原因不伪装已定位。 |
| UA-14 | 改组成员、线路或执行节点常用操作。 | 显示现有服务影响，重新核对执行条件；记录局部结果与恢复情况。 |
| UA-15 | 专用出口到期、撤销与再次分配。 | 确认停用并手动回收后才可再分配，实际固定独享证据另验。 |
| UA-16 | 新节点完成登记、接入、授权和订阅验证。 | 每个阶段有明确结果；真实连接、计量与未授权访问验证有独立证据。 |
| UA-17 | 资源仅在外部面板存在或出现未识别差异。 | 保留未关联或差异状态，不猜测归属，不无条件覆盖。 |
| UA-18 | CPU、延迟、速率等深度指标。 | 机器、位置、方法、单位和时间明确；缺失采集不伪造结果。 |
| UA-19 | 中文与桌面、手机的完整操作。 | 列表、筛选、菜单、弹窗、错误及空状态可用；英俄基础键齐全。 |
| UA-20 | 高级维护跳转、日志与订阅凭据检查。 | 管理员权限有效，凭据不进 URL 或日志；日常 F01～F05 无需跳转。 |

验收记录须包含版本、环境、场景、实际结果、测试或截图位置和未验证项。对不支持的能力记录缺口及后续安排，不得把跳过、仅模拟或无数据写成通过。

| 专用出口故障与更换 | 已确认管理员人工核验与确认，不自动切共享出口；通知及费用调整仍未定，不因此改变已有条款。 |
| 告警与历史 | 到期或额度阈值、外部通知渠道、采集与保留成本；未经确定不自动向客户发送消息。 |
| 节点写能力 | 当前版本支持哪些常用操作，执行成功如何核验；以隔离验证结果形成能力清单。 |
| 现用节点接入 | 明确机器、现有业务影响、部署方式与恢复措施；不复用含糊的“新增节点”授权执行重装。 |

接口字段、兼容性和性能等技术事实优先查本地资料、代码及隔离环境，不把可自行核实的问题反复交给用户。涉及未定业务规则或不可推断的实际资源选择时及时询问。不要为该指南预设采购、工期或可用性承诺。

## 13. 后续每次更新的执行规则

1. **开始前：**阅读 AGENTS.md、需求基线、本指南、相关产品设计与实施计划；改代码前完整阅读 CONTRIBUTING.md。存在 CodeGraph 时按项目约定先使用，不自行创建索引。
2. **说明归属：**指出本次对应的 UC 工作包、客户或节点问题、流程与验收编号。维护修复可引用相关约束，不为每次小修新增工作包。
3. **先复用：**核查当前源码、两个共享组件消费者和已有生命周期；修复已有逻辑，不重建平行业务系统。
4. **控制边界：**字段与布局可在本指南内细化；改变业务规则、整合边界或现用资源处置须先确认并同步文档。不得把未决定事项悄悄写进默认值。
5. **完成实现：**接口、权限、页面、语言、任务结果和必要恢复构成同一交付；对仅完成部分的工作明确标记。
6. **分层验证：**按 CONTRIBUTING.md 的变更矩阵执行检查；业务与界面通过之后，另行记录真实节点、客户端与出口证据。
7. **更新进度：**在实施计划登记实际结果、版本、证据和遗留项；需要调整规格时修改本文对应章节，避免另建冲突方案。
8. **提交与发布：**遵循现有提交、生成产物和 CHANGELOG.md 规则。方案确认、代码合入、本地通过和线上交付是不同状态，不能相互替代。

后续智能体和开发者都从 AGENTS.md 进入本指南。文档更新不会自动给其他对话发送消息；正在进行的工作仍需读取当前仓库版本后对齐。
