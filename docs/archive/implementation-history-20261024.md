## 1. 已确定的目标

- 基于 Minishop 二开，复用账号、权限、现有界面和主要技术栈，统一改造套餐业务。
- 一期服务熟悉订阅的用户，交付网站、运营后台和通用客户端接入；不接在线支付，自有 App 后续开发。
- 一期用户网站与运营后台支持简体中文，覆盖实际开放流程、状态与错误提示，配套中文客户端教程；中文阅读路径中的文档正文、导航与提示也需全中文，保留现有英俄基础语言及俄语选项。
- 管理员自由配置套餐。多节点／单人单 IP 是资源维度，总流量／每月额度是计量维度，价格、流量和有效期由管理员设置。
- 一个账号可拥有多份服务，各自计量、到期和停用；同一服务在不同节点消耗同一份额度。
- 以客户与节点为两条管理主线，统一网站入口、管理账号、查询、日常操作和节点接入流程；保留 Remnawave 执行层与低频高级维护入口，按统一管理台指南分批实施。
- **使用体验优先，服务端执行限额并尽量减少超额。** 用户最新决定替代此前严格零超额要求；不为绝对保证预先增加额度预分配或代理内核改造。

## 4. 一期限额实现原则

业务模块定义每份服务的额度、周期、有效期和节点权限，Remnawave 负责节点身份级计量与限制，业务 worker 做同步和核对。所有节点的同一服务消耗汇总到同一身份，不能每个节点各获得一份完整套餐额度。

- 额度确认耗尽或服务到期时，执行服务端限制；验证新连接和已建立连接都得到正确处理。
- 同步失败保留已有用量和最后更新时间，告警并重试，不清零或自动恢复已停用服务，不把暂时未知直接视为耗尽。
- 并发、高速下载、长连接及故障恢复场景必须测量实际超额与延迟，再决定同步频率和优化方式。当前不承诺超额必然很小，也不将体验优先解释为无限量使用。
- 旧 3x-ui 凭据不会自动受新套餐限制，后续节点接入时明确处置；当前不改动现用节点。

持续故障的处置时间和告警规则在节点对接时设计，不预先增加一套分布式预算系统。

## 5. 关键验收

1. 管理员新增套餐不改代码；开通记录和用户服务保存正确的条款、价格及有效期。
2. 一个账号持有两份服务，使用、暂停、到期和续期分别生效；账号封禁覆盖全部服务。
3. 同一份服务在两个节点同时使用，正确汇总业务上传和下载量，确认额度耗尽后只停该服务，另一份服务不受影响。
4. 测量接近额度时的长连接、并发连接及一期支持的协议的停用延迟与实际超额量，不通过截断页面用量隐藏问题。
5. 节点或面板断连、进程重启、重试、月度切换和恢复备份，不重复发放权益或将已用量错误清零；暂时统计失败不误停正常服务。
6. 通用客户端导入、刷新和保留旧配置，都不能扩大服务端权限或额度。
7. 单人单 IP 的真实出口与资源分配一致，不与其他用户重复分配；无实际资源时不宣布该能力通过。
8. 用户与管理员可用简体中文完成一期开放流程；语言切换、刷新、错误提示、菜单和弹窗在桌面/手机上均可用，客户端教程与实际交付一致。
