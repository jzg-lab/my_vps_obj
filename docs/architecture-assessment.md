# 我的 VPN｜架构决策

本文解释已经采纳的结构和取舍。准确模块位置见[架构概览](architecture.md)，业务约束见[需求基线](requirements.md)，完成状态及验证范围只在[实施计划](implementation-plan.md)维护。

初始 Minishop v3.8.2 源码调查、候选方案和离线实验保存在[历史架构评估](archive/architecture-assessment-20261024.md)。其中“尚未实现”“未接入”属于当时结论，不是当前开发任务。

## 1. 为什么采用核心二开

用户要求一个账号同时持有多份独立服务，而上游常规路径围绕主要连接身份和当前单份订阅组织。增加数据库记录、套餐卡片或节点分组，不能自动解决各份服务的计量、到期、停用与账号生命周期。

因此采用核心二开，复用账号、权限、界面和工程基础，在本仓库统一维护服务业务。插件继续用于适合的扩展，不作为多服务完整生命周期的替代，也不复制单独交付的 PRO 实现。

## 2. 统一产品，保留执行层

| 组件 | 负责 | 不负责 |
| --- | --- | --- |
| 用户网站与管理台 | 同一账号入口、用户服务、客户与节点日常管理 | 转发实际代理流量。 |
| 本项目后端与业务库 | 模板、服务权益、用量核对、资源占用和操作记录 | 直接修改 Remnawave 数据库。 |
| 现有 worker | 交付、同步、重试、周期和结果核对 | 在结果未知时无条件重放权益变更。 |
| Remnawave Panel | 远端身份、授权组、线路及节点控制 | 自行决定本项目的套餐规则和业务周期。 |
| Node／Xray | 连接执行和计量来源 | 将网站显示或接口受理当作真实连接结果。 |
| 通用客户端 | 获取当前服务配置并连接节点 | 决定额度或绕过服务端权限。 |

业务网站和管理台在同一仓库协作；Panel／Node 独立运行，不把“统一管理”误解为合库、改框架或另建一批微服务。低频复杂底层配置通过受控高级维护入口处理。

## 3. 一账号，多服务，一服务一身份

`账号 → 多份独立服务 → 各自连接身份 → 获授权节点／出口`。

- **模板**定义产品条件；**服务**保存具体账号的权益与快照；**操作记录**保存一次开通或变更的意图及结果。
- 同一账号可重复开通同一模板。新服务不替换其他服务、不合并额度、不自动跨服务消费。
- 连接和资源通过稳定 ID／UUID 关联，不凭姓名、邮箱、IP 或显示名称猜测归属。
- 封禁、解封、删除、合并必须覆盖账号涉及的所有服务；单服务操作只改变该服务。
- 模板额度统一调整是已确认例外，其他历史条款保留快照，详见需求与计量契约。

## 4. 数据责任与执行结果分开

本项目业务记录是权益依据，节点观测是执行证据。业务允许、任务受理、远端配置已核对和真实连接可用不是同一个状态。

网络超时可能代表结果未知。按原请求和目标版本查询核对，不能直接重复开通、续期、回收或重置额度。恢复操作检查最新归属和权益；失败历史、被新意图取代和人工核对必须可追溯。

资源预览需覆盖受影响客户与服务，提交时重新核对。专用出口更换保留停用、占用和人工核验约束，按权益申请恢复；不以自动切共享出口掩盖故障。

实现契约见[独立服务接口](development/independent-services.md)、[权益与计量](development/entitlement-metering-contract.md)及[交付与出口](development/service-delivery.md)。

## 5. 计量与隔离不能靠页面保证

上传加下载的业务载荷按服务身份累计；同一服务跨节点共用额度。节点网卡量、订阅下载次数和业务计费量不能混用。

月度额度采用北京时间日历月和原始开通锚点，周期切点持久化后重试沿用。续期不清零用量，异常缺失需要准确核对；用户选择体验优先，不承诺绝对零超额。

按身份精准断连属于经过单独授权的最小 Node／Xray 适配，必须固定版本并验证目标旧连接终止、旧配置拒绝及同源另一份服务继续。**标准镜像与隔离适配的结论分别记录**；验证一个固定协议不能证明所有入站和生产环境均安全。当前接入状态见实施计划第 14 节。

## 6. 环境与证据边界

- 开发优先使用[隔离项目环境](development/project-local.md)；通用开发环境和上游安装器是不同用途。
- 模拟页面、真实数据库、真实 Panel、Node 数据面、原生客户端、图形客户端和生产发布分层验证。
- 公网固定独享须核对实际出口与资源独占，不能用两个容器的内部 IP 或同机并行进程证明。
- 旧 3x-ui 与新 Node 的身份、用量和授权不会自动合并；现用节点操作必须有具体影响和恢复安排。
- 默认环境配置、已有数据与生产镜像不因某项测试成功自动改变。

上游升级、独立迁移、客户端兼容、执行层补丁和恢复演练都存在持续维护成本。后续取舍依据当前代码和证据，不根据最初候选方案重新搭建工程。

## 7. 更新这些决定时

先指出要改变的业务规则或技术边界，核实实际调用方和既有契约。已确认约束内的实现细节可自行选择；新业务规则、范围或生产资源处置取得明确决定后同步需求、指南及实施计划。

不在这里累加每轮测试数字。历史调查只用于解释当初为什么选择二开，当前源码结构以架构概览和实现为准。
