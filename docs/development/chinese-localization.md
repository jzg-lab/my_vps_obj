# 简体中文与客户端体验

<a id="简体中文与客户端体验c-包"></a>

本文说明语言选择、文案维护、服务教程和文档演示的技术职责。业务要求以[需求](../requirements.md)
和[产品设计](../product-design.md)为准，开发规则见[贡献指南](../../CONTRIBUTING.md)。
本地化不改变额度、权限、生命周期或部署默认值；接手入口见[接手指南](../handoff.md)。

## 语言路径

- 网站和后端统一使用 `zh-hans`，语言名称为“简体中文”。`zh`、`zh-CN`、`zh-SG`、`zh-Hans` 及 `zh-Hans-*` 输入规范化到该代码；`zh-TW`、`zh-Hant` 不自动视为简体。
- `JsonI18n` 自动读取 `locales/zh-hans.json`，保留 `en`、`ru`。不复制英文文本充当中文，也不改变既有回退顺序。管理员的运行时覆盖仍优先。
- 首次页面通过 URL `lang`、语言 cookie、浏览器语言、默认配置依次匹配。登录后继续使用账号偏好；现有 `/api/account/language` 保存选择并使用户缓存失效，语言 cookie 让刷新前的启动页保持一致。无需新 API。
- 后台继续按需加载 `admin` scope；用户页面使用 `webapp` scope。根页面 `lang` 随当前语言同步，让辅助技术正确朗读。
- 管理员可在现有“默认语言”设置填写 `zh-hans`；文案修改不代替部署配置变更。套餐名称、品牌、IP、邮箱、凭据和管理员自定义内容保持原样。
- 内嵌教程兼容 Remnawave v1 配置的 `zh` 字段。已有 `localizedInstallValue` 按基础语言读取，无需修改第三方面板或更换 i18n。
- 服务日期继续使用 `Asia/Shanghai`，语言切换不改变业务边界；界面明确标注北京时间。

## 覆盖与持续补齐

中文维护范围包括用户登录、账号安全、客服、服务目录／详情，以及后台客户、节点、服务操作、套餐、资源、账号生命周期、历史、通用控件和开放设置。
仍开放的文档、备份、外观、插件、翻译、日志、群发和广告页面同样纳入，包含富文本编辑器、表情库、配置诊断和操作错误。认证、通知及客服邮件也使用相同语言资源。翻译不会启用旧支付、礼品或推荐业务。前端演示构建读取中文资源，测试不能只在翻译函数里模拟中文。

`tests/contracts/test_chinese_locale.py` 检查服务/状态前缀、开放页面中的直接翻译调用和一期设置 manifest；新增服务键缺中文会失败。全部中文键还要存在英俄基础键，保留占位符计数及富文本标签。动态组合键需在该测试的前缀或对应页面测试中覆盖，不能只写组件 fallback。

新增页面由实现者同步增加 en/ru 基础键与 zh-hans 条目，扩展契约范围及场景，再运行 locale contract、类型检查和受影响桌面／手机流程。不能把维护职责留给已经结束的历史 C 分包，也不能从局部测试范围推断整个上游语言包已翻译。

## 客户端教程

[中文客户端教程](../user-guide/clients-zh.md) 按选择服务、官方安装、导入和更新组织。仓库中的 `deploy/examples/independent-services-guides.json` 可通过现有 v1 教程配置加载，含中文、英文、俄文：Android/iOS 各 3 款，Windows/macOS/Linux 各 4 款，Android TV 1 款、Apple TV 2 款。电视只列有官方支持依据的候选。

客户端候选和来源由[中文教程](../user-guide/clients-zh.md)维护。更新候选时核查官方仓库、发行信息和商店的平台／收费要求；无法确认精确最低系统版本时如实注明，不由安装包名推断兼容。YAML、URI 等输出差异须分别说明。
列入教程不代表通过客户端认证：原生 Mihomo 的验证范围不能推广为各平台 GUI 或全部候选客户端通过。实际证据统一见[实施计划 §14：本轮本地最终验收](../implementation-plan.md#本轮本地最终验收)。

示例只有品牌、Logo、客服及订阅占位信息，不修改运行配置。独立服务教程从随 backend 镜像打包的示例读取纯配置，不经过已退役的 `/api/subscription-guides` 或旧账号面板身份；`{{SUBSCRIPTION_LINK}}` 只由当前服务已核验的交付响应填入。无需额外运维配置，修改教程则需验证 JSON 并重建镜像。契约检查调用既有 v1 validator，并检查七个平台的候选数量、四步流程、三种语言及链接边界。

## 文档与演示

中文阅读路径包括根目录说明、贡献与安全指南、完整更新日志、`docs/` 正文，以及部署和插件示例说明。文档站的导航、社区作品目录、邮件预览和 API 参考使用中文；API 的接口标题、分类、模型说明及生成的事件／面板兼容性目录由中文源目录生成。新增接口必须补充中文标题，生成器与契约检查会阻止遗漏。

API 路径、字段、命令、字体品牌、协议标识和历史来源链接保持原样；历史俄文章节锚点继续支持旧链接。显式英文替代文档 `README.en.md` 与历史生成报告不属于中文文档入口。上游安装脚本仍保留其原始语言，中文迁移指南解释对应提示，不能把脚本运行输出算作已汉化界面。

文档演示默认使用独立服务和简体中文。内嵌页仅在没有已保存语言偏好时采用中文默认值；用户选择俄语或英语后，刷新与重新打开继续保留。演示场景提供独立服务、尚未开通、登录与注册及中文事务邮件；旧场景的显式链接继续兼容。服务详情中的连接教程只使用演示订阅地址，不代表真实交付。文档演示的默认语言不改变正式部署配置。

项目自有 README 拼图、主题预览及文档截图通过现有生成器维护，不手改生成产物。第三方主题目录使用明确标注“非界面截图”的中文简介封面，并保留作者链接和原图归档。中文模式下的匿名演示姓名、消息、套餐和地区使用中文，真实账号及管理员自定义内容不经过这层转换。

## 覆盖边界与验证

一期隐藏的上游销售、推荐和单订阅流程不计入开放页面验收；不以现有中文契约检查推断整个上游语言包已翻译。
保留俄语选项、基础资源及翻译编辑器的俄语原文，不改成中文冒充俄语支持。
模拟页面通过不等于真实会话、面板、节点、订阅导入或专用出口通过。

定向检查在隔离工作区使用项目 Python／Node 依赖：

```sh
python -m pytest -q tests/contracts/test_chinese_locale.py tests/contracts/test_chinese_documentation.py tests/contracts/test_admin_locale_keys.py
npm --prefix frontend run test:e2e -- chinese-services.spec.ts chinese-service-guide.spec.ts theme-library.spec.ts backups-upload.spec.ts
```

完整检查命令 `npm run check` 和文档构建 `npm run build:docs` 的适用范围以贡献指南为准。
文档与截图生成集中安排，避免共享工作树中并发生成覆盖。模拟浏览器不连接数据库或面板；
真实站点验证使用[项目隔离环境](project-local.md)，不能拿现用生产节点作本地化测试设施。

桌面／手机均需核对菜单、展开状态、弹窗、长文案、缺失键和语言保存后刷新；
文档站另检查正文、导航、搜索、API 控件及演示。中文展示不得改写协议路径、代码块、凭据或管理员自定义内容。
