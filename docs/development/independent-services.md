# 独立服务：数据模型与接口

需求依据：[需求基线 v0.11](../requirements.md)、[产品设计 v0.11](../product-design.md)。

当前已实现数据层、API、管理员套餐/资源/开通页面、用户多服务首页、账号生命周期同步和后台历史查询，不代表节点连接已经交付。旧 `subscriptions` 的字段、支付与节点同步逻辑不作为新服务的额度来源；网站旧业务接口、旧回调与核心后台任务已关闭；后台旧操作与配置已收拢，Telegram 旧权益入口也已停用并导向网站。

## 数据关系

```mermaid
erDiagram
    users o|--o{ user_services : owns
    service_plans ||--o{ user_services : opens
    user_services ||--o{ service_orders : records
    user_services ||--|| service_connections : connects
    user_services o|--o| dedicated_exits : reserves
```

- `service_plans`：可编辑模板、版本和启用状态。总流量和月度额度共用条款结构，资源类型与计量规则独立。
- `user_services`：用户实际获得的服务，保存开通条款、独立额度、用量、时间和预期状态。没有“账号只能有一份当前服务”的唯一约束。
- `service_orders`：管理员操作记录，保存操作者、请求幂等键及价格/条款/日期快照。人工开通没有伪造付款记录或付款成功状态。
- `service_connections`：每份服务独立的连接身份；创建服务先预留身份名称，面板编号未创建前为空。准备 worker 会核对并绑定禁用状态的独立身份，仍保留 `pending`，直到计量与交付就绪。不会写入 `users.panel_user_uuid`。
- `dedicated_exits`：实际资源清单。IP 和节点权限组唯一，资源与服务为一对一占用；录入资源不等于通过真实出口核验。

迁移 `0107_user_services` 只追加新表和索引，不改变原有订阅记录。测试在临时 PostgreSQL schema 上重复执行迁移，验证幂等；不会运行到线上节点。

## 接口

所有接口沿用 `{ok: ...}` 响应、现有登录会话与管理员权限。用户查询始终取会话账号，不接受客户端指定他人的账号作为身份。

| 方法与路径 | 用途 |
| --- | --- |
| GET `/api/admin/service-plans` | 分页读取套餐模板 |
| POST `/api/admin/service-plans` | 创建模板 |
| PUT `/api/admin/service-plans/{plan_id}` | 以 `expected_revision` 校验版本后修改模板，只影响后续开通 |
| POST `/api/admin/services` | 管理员为指定账号开通一份服务，携带模板版本与 `idempotency_key` |
| POST `/api/admin/services/{service_id}/changes` | 保存指定服务的暂停、恢复或续期，携带所属账号、服务版本和幂等键；由 worker 核对面板 |
| GET `/api/admin/services?user_id=...` | 查看指定账号的多份服务 |
| GET `/api/admin/service-orders?user_id=...` | 查看该账号的开通快照 |
| GET `/api/admin/services?deleted=true` | 分页查看已删除账号的服务历史，仅管理员可访问 |
| GET `/api/admin/service-orders?deleted=true` | 分页查看已删除账号的开通快照；不与 `user_id` 同时使用 |
| GET `/api/admin/users/{user_id}/access-sync` | 查看封禁/解封的持久化同步状态 |
| POST `/api/admin/users/{user_id}/access-sync` | 重试已有同步任务，不改变封禁决定 |
| GET/POST `/api/admin/dedicated-exits` | 查看或登记专用出口资源；登记后未验证 |
| GET `/api/service-catalog` | 当前账号可查看的启用套餐；只返回商业条款，不暴露节点组 UUID、资源池或后台版本信息 |
| GET `/api/services` | 当前账号的服务列表 |
| GET `/api/services/{service_id}` | 当前账号的某份服务；其他账号的 ID 返回 404 |

列表使用 `limit`（1～200，默认 100）、`offset`（默认 0），返回真实总数 `total`。具体请求类型见生成的 [OpenAPI](../openapi.json)，前端类型由同一文件生成，不手工维护副本。

两个 `service-orders` 查询作用域都支持可选的 `service_id`（32 位小写十六进制 ID）以筛选一份服务的开通记录；仍必须指定 `user_id` 或 `deleted=true`，服务筛选不能扩大账号范围。分页总数与列表使用相同过滤条件。

开通操作在同一数据库事务中锁定用户、模板及指定资源，提交服务、连接身份和订单。相同用户重复提交相同幂等键与相同请求，返回原服务；键相同而条款选择不同返回冲突。客户端必须在超时重试时保留原键，明确执行另一次开通时才生成新键。

## 后台操作入口

- `/admin/service-plans`：创建、编辑套餐。资源类型和流量规则分别选择；管理员填写价格、币种、有效期和流量。流量输入使用明确标注的 GiB（1,073,741,824 字节），保存时转换为整数字节，编辑不会损失原有字节额度。价格以十进制字符串提交。
- `/admin/dedicated-exits`：登记 IP、资源池及对应节点组，查看是否绑定及是否验证。登记不会自动标为“已验证”。
- 用户详情的“Independent services / Независимые услуги”：查看每份服务，选择套餐和空闲专用资源后手动开通。同模板可再次开通；列表不汇总成账号统一余额。
- `/admin/service-history`：分页查看已删除账号的服务，逐份打开开通历史。正常用户详情中的每份服务也有同一个历史入口。历史弹窗显示原套餐名称、版本、资源类型、价格、额度规则、有效期、操作人和记录时间；只读取已保存的开通快照，缺失或不支持的快照显示不可用，不回退到当前模板。价格是开通条款，不代表付款确认。归档页不提供开通或恢复登录入口。
- 开通前显示所选模板的额度、有效期和价格；发送模板版本，遇到并发修改提示刷新。网络或服务器错误导致结果不明时，浏览器会话保存原请求，重新打开弹窗后使用相同幂等键重试；不会自动改成另一套条款。此数据不包含连接凭据。
- 列表显示真实总数并分页；开通选择器读取全部分页，避免第 201 项以后无法选择。模板编辑和资源登记采用已有表单、下拉、对话框及表格组件。

实际 bootstrap 也向后台传递独立服务模型：旧单订阅、赠送、套餐营销和统计页面退出导航，旧直达链接回到服务套餐页。用户详情和列表不再展示账号级订阅状态、额度、套餐调整或连接重置；封禁、合并、删除及历史仍可用。旧订阅筛选会从收藏链接中清除。设置及搜索隐藏旧定价、支付、试用、奖励与账号默认额度，登录、面板 API、客服及备份设置保留。历史支付只读，不能再发放或冲正旧权益。旧网站接口仍返回 410，旧权益 worker 不再启动。Telegram 已改为网站服务入口；完整中文界面和连接交付仍待完成，不能按最终产品交付验收。

## 用户页面

实际服务端 bootstrap 固定返回 `serviceModel: independent`，用户首页使用“我的服务 / 套餐目录”。这不是管理员可切换的双业务开关；保留不带该标记的上游演示夹具，仅用于兼容回归。

- 我的服务按独立 ID 分卡片，支持同模板多份服务和分页；详情重新读取当前账号拥有的记录。
- 每份卡片显示实际用量、额度、剩余量、到期时间、月度边界和最后同步时间。进度条最多显示 100%，数值不截断；超额另行列出。尚未同步明确标注。
- 专用 IP 详情分别展示分配地址和核验状态；准备中的服务没有伪造的订阅链接。
- 套餐目录只列启用模板，展示人工开通说明、额度、有效期和价格，没有申请、支付或自助激活按钮。模板更新不改已开通服务的快照。
- 保留设置、安全、通知和客服。旧购买、试用、加购、赠送和营销界面在此模式不渲染；旧用户页及购买直达链接返回服务首页，不触发促销码激活。邮箱绑定及密码对话框仍可用。
- 日期统一显示北京时间。列表或详情失败时显示错误和重试，切换页面/关闭详情时取消旧请求，避免把过期响应显示在另一页。

## 旧业务运行边界

网站应用固定启用旧业务停用策略，不受管理员支付/套餐开关影响。旧接口保留路由以返回明确的 HTTP 410 与 `legacy_business_retired`，不执行原处理器；需要登录或管理员权限的路径仍先检查权限。

- 停用旧订阅读取和交付、购买/续费、试用、激活码、礼品、余额、分销、自助设备操作与旧账号级额度/套餐修改；后台旧财务历史读取保留。登录和 Telegram 绑定后的隐式欢迎赠送同样停止。
- 独立服务接口、账号登录/安全/合并/封禁/删除、客服、设置与备份入口保留。
- 单独的 webhook 监听器对已配置的旧支付回调和账号级面板回调返回 410，不解析或入队。新身份准备单独运行，不将旧面板事件套到新服务。
- 核心 worker 启动独立身份准备、服务变更同步、账号访问同步、出站设置刷新、管理员广播和备份；旧流量恢复、自动续费、礼品、分销、订阅通知、支付对账和全量旧面板同步不再注册。
- 启动时恢复的旧 `yookassa`、`panel`、`panel_sync` 队列事件直接移入现有 dead-letter 队列，保留原载荷供核对。移入失败时不确认消费，也不执行旧处理器；未知扩展事件继续沿用原有重试规则。此处不修改独立插件契约，任何另装插件的权益写入必须另行审查。
- OpenAPI 将停用接口标记为 deprecated，并给出 410 契约；保留的历史 200 schema 只用于上游类型兼容，不代表部署会返回旧业务结果。

Telegram 根路由使用内层中间件，在路由与管理员权限过滤之后拦截核心旧试用、购买、激活码、推荐奖励、账号级额度和面板同步处理器，也清除对应旧会话状态。主菜单导向网站的独立服务和客服，管理员菜单保留账号操作并链接套餐后台；注册、语言、封禁、删除及插件路由契约保留，注册不再隐式赠送旧权益。旧支付按钮不能创建账单，pre-checkout 明确拒绝；已成功付款的历史 Telegram 收据以原金额、币种和交易编号进入现有队列，再转入 dead-letter 供人工核对，不发放权益或自动退款。入队失败会报错，不能视为已经保存；该机制不承诺 Telegram polling 在异常时自动重投，队列保留期限仍遵循现有运维配置。内联查询不再发布旧购买或礼品结果。

当前本地配置关闭 Telegram，以上用路由测试验证，未发送真实 Telegram 消息。停用旧 Web 回调和 worker 不会撤销已有节点凭据，也不能让现用 3x-ui 凭据自动受新套餐限制；本次没有连接或修改现用节点。

## 账号合并与删除

追加迁移 `0108_service_account_history` 允许服务/订单所属账号为空，已有记录保持原归属；订单的 `request_owner_id` 回填为原账号 ID，幂等唯一性改为原请求账号加请求编号。该字段是历史标识，不是有效登录账号的外键，不能用它恢复访问权。

- 合并账号在双方用户行锁下仅迁移服务和订单归属，不合并额度、日期、连接身份和专用资源绑定。原始请求作用域不改，两个账号相同的请求编号也可共存。
- 删除入口（网站和 Telegram 管理）锁定用户，先检查专用出口已经回收，再处理所有连接。每份独立连接在删除后都必须查询得到明确“不存在”的结果，不能只凭删除请求的成功响应（包括 dry-run 模拟成功）继续；网络故障不能当作已删除。
- 当前尚未投递的 `pending` 且无面板身份记录可以取消；未确认的投递错误阻止删除。后续身份投递实现必须在远端调用前记录操作状态，不能把结果不明的投递当成“从未创建”。
- 完成撤销后，服务设为 `cancelled`、连接设为 `revoked`，服务和订单 `user_id` 置空，原条款、额度、用量、日期、价格快照及审计标识保留。直接调用删除 DAL 也必须满足已撤销和无绑定的前提。
- 历史可通过上述管理员 API 和 `/admin/service-history` 页面查询，返回真实总数和分页；用户接口不能查询其他账号或已删除账号的历史。
- 开通和删除共用用户行锁，避免删除进行中再开通服务。被删除或合并的原账号不能重放旧开通请求来获取已脱离其归属的服务。

## 当前约束与后续工作

- 用户封禁后不能新开通，用户接口不返回其可用服务；全部已知连接进入下述持久化同步流程，真实节点停用效果仍需验收。
- 新服务显示等待交付。当前接口不输出订阅凭据，不将预留名称或已准备的禁用面板身份当作可用连接。
- `used_bytes` 保留实际值，不截断到配置额度；尚未同步时 `last_usage_sync_at` 为空。
- 月度边界函数按北京时间保留原开通锚点，覆盖月底和闰年。周期切换与节点计量核对尚未接入，不能把此函数的测试当成月度套餐实际验收。
- 专用 IP 分配在数据库中防止重复占用，尚需证明实际网络出口的固定和独占条件。
- 合并和删除已接入服务历史处理；核心旧单套餐入口已停用，独立连接交付仍需完成。保留 RESTRICT 外键，删除流程显式解除归属，不使用级联删除服务历史。

## 封禁、解封与故障重试

追加迁移 `0109_account_access_sync` 为每个有变更的账号保留一条同步记录，并为升级前已封禁的账号补任务。网站和 Telegram 管理入口共用同一实现：先在用户行锁内保存封禁决定与任务并提交，再调用面板。远端故障不会撤销已经保存的封禁。

- 覆盖旧订阅关联的全部有效身份和每份独立服务身份；单个身份失败不阻止处理其他身份。后台 worker 每轮处理最多 50 个待处理账号，轮末等待 30 秒再重试；进程重启后继续读取数据库任务。网络耗时会增加实际重试间隔。
- 解封逐份检查原服务状态、起止时间、额度和专用出口验证情况。到期、耗尽、暂停、取消或连接未就绪的服务继续停用；不重置流量和日期。
- 每次写入后重新查询面板状态。写请求成功或 dry-run 成功不能代替查询确认；未知结果继续等待。面板中不存在的身份可视为已禁用，但不能视为已启用。身份投递结果不明且没有远端编号时保留待核对任务。
- 同步、开通、合并和删除共用用户行锁。新的封禁/解封决定不会被旧同步覆盖；合并会把来源账号未完成的同步意图带到目标账号。
- 用户详情显示“等待同步”“面板状态已确认”或“未请求变更”，可刷新、重试；等待时每 15 秒刷新。账号已保存但连接尚未同步时，不显示普通完成提示。

**确认范围是面板状态。** 目前尚无真实 Node；长连接断开、节点失联和实际流量限制仍属于隔离连接验收。回退到不运行此 worker 的旧版本前，必须处理待同步记录并核对远端状态，不能依赖旧版本继续重试。

## 升级与回退边界

`0108` 是追加迁移，不修改旧迁移。应用迁移前保留数据库备份；已有订单先回填原请求账号，再替换幂等约束。发生账号删除后，历史记录的所属账号可能为空，因此不能直接回退到要求非空账号的旧代码或重新施加非空约束。实际生产回退需恢复匹配的代码和数据库备份，并重新核对面板状态；当前只在隔离本地环境验证。

## 独立连接身份准备

追加迁移 `0110_service_provisioning` 保存每份连接的尝试时间。`ServiceProvisioning` worker 只在面板 live 模式启动，每轮按最久未尝试顺序处理最多 50 份待准备服务，再等待 30 秒；本地默认 dry-run 不运行该任务。切换写模式后需要重启 worker。

- 使用固定的服务身份名称和服务 ID 标记，创建禁用身份；不附带账号邮箱、Telegram ID，也不写入账号旧面板绑定。共享套餐使用开通条款中的节点组；专用套餐必须先有已核验、启用且资源池匹配的独占分配。
- 每份身份独立下发额度和到期时间，采用 `NO_RESET`，不套用面板默认自然月重置；业务月度切换仍待接入。创建请求成功或 dry-run 返回成功不算绑定成功，必须重新查询真实身份。
- 远端调用前持久化“待核对”状态，之后与封禁、合并、删除共用账号行锁。超时或崩溃后按同一个服务身份核对，不随机另建身份；姓名相同但归属标记不符时拒绝认领。合并期间归属已改变的任务留待重试。
- 确认归属后保存远端编号，再核对禁用状态、精确节点组、额度和到期；配置不符时保留错误，不覆盖面板已有用量。已绑定身份缺失不会自动重新创建，以免意外补发额度。
- 准备完成仍为 `pending`，远端仍为禁用。下一步接计量同步、恢复额度和订阅交付，不能将此状态称为可连接；账号解封也不会启用这些待交付服务。

## 单份服务暂停、恢复与续期

追加迁移 `0111_service_changes` 为服务保存操作版本，为连接保存待同步标记、错误、尝试和确认时间。管理员在用户详情选择一份服务的“Manage service / Управление”，选择暂停、恢复或续期。归档服务没有变更入口。续期的天数、价格、币种由管理员明确填写；价格仅作操作记录，不接支付。

- 变更与开通、账号封禁、合并、删除共用账号行锁。请求必须匹配当前所属账号和服务版本；同账号的幂等键不能被另一份服务或另一种操作复用。
- 服务决定、版本、待同步标记及操作快照在同一事务提交。重复请求返回原记录，不再次延长时间。浏览器会话保留结果未知的原请求，关闭再打开后继续原请求；明确被拒绝才允许刷新后发起新操作。

## 独立用量采集

追加迁移 `0112_service_usage` 保存每份连接上次确认的累计流量、采样尝试时间和错误。`ServiceUsage` worker 在 live 模式下每轮最多读取 50 份已绑定且未撤销的身份，优先处理最久未尝试的记录，轮间等待 30 秒；不使用 dry-run 的模拟零用量。

- 读取与开通、续期、封禁、合并和删除共用账号锁，重新核对服务归属、面板 UUID、身份名及归属标记；没有绑定的服务不采样，不借用账号的旧身份。
- 面板 `userTraffic.usedTrafficBytes` 与 `lifetimeUsedTrafficBytes` 必须是有效的非负整数。新身份保持 `NO_RESET` 且两值相等；外部重置或策略变化先报告异常。累计计数不能回退。接口未知、缺字段、类型错误、身份冲突及回退均保留已有用量和最后成功同步时间。
- 读取超时等暂时错误自动重试；计数回退或重置会保留需要核对的状态，不因后续数字再次上涨而自动清除。当前不提供未经核对的“清零/重试修复”按钮；人工计量核对与恢复流程在连接交付前补齐。
- 只把累计计数相对上次确认值的增量加入该份服务，重复采样和并发采样不重复累计；首次采样保留已有确认量，不二次计入。超过额度的用量原样保存和展示，不截断为套餐额度。
- 用户与后台返回同一个 `usage_error` 字段并显示同步未确认提示；`last_usage_sync_at` 仅在有效采样成功后更新。暂停、封禁及到期身份仍可采集迟到用量，不因此恢复权限。
- 此 worker 只采集，不调用面板重置、更新或启用接口，不推进月度边界、不标记连接 ready。后续月度切换会基于累计观测划分业务周期，不能用重置面板计数来绕过重试核对。

### A3 模板额度与准确计量恢复

用户确认模板额度调整统一影响同模板全部仍归属账号、未取消/撤销的服务，覆盖当前和未来周期。`ServicePlanQuotaChange` 记录每次模板额度变更的操作者、原因、版本和额度；worker 在各账号锁内应用最新版本并写入每份服务的 `quota` 操作记录。已有开通和周期结算快照不改，价格、名称、资源、有效期、原月锚点和真实已用量不改；额度调低后允许显示超额并执行限制。未开启 live worker 的 dry-run 环境仍等待应用，不伪造远端确认。

计数回退/重置后，管理员先暂停该服务并等待面板确认停用，再在“管理服务 → 核对用量”填写：准确核对的跨周期累计业务字节、此次核对的面板原始计数、核对来源和说明。必须使用准确记录，不接受估算或降低已确认累计用量；身份、版本、原始读数或 NO_RESET 策略不符会拒绝。请求幂等重放不会再加用量，审计保留前后用量及核对依据。

恢复保存逻辑累计量与原始计数的映射，后续只加原始计数增量，面板绝对限额也使用同一个映射；不重置计数、不新建身份、不抹去既有用量。服务保持暂停，由管理员另外执行恢复。面板的停用状态不代表真实 Node 已停止全部长连接，仍须真实资源验收。

A 包接口检查点验证：完整后端回归 5,587 项、631 个子测试通过，45 项环境条件跳过；全量 mypy 覆盖 1,340 个文件，前端静态检查与 1,492 项单元测试通过。其后对最后同步时间显示及新增 PostgreSQL 用例做定向复验。新迁移/并发 PostgreSQL 测试、浏览器构建与桌面/手机场景尚待统筹分配的资源时段；真实 Node 未验证。不可将此接口检查点写成整个 A 包验收完成。
