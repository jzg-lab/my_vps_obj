# 独立服务交付与专用出口

本文说明服务级订阅、交付、撤销和专用出口的接口与失败恢复约束。
对应[统一管理台指南](../admin-console-guide.md)的 F01、F04、F05、F07，覆盖 UC-04～UC-06
及 UA-09～UA-12、UA-14～UA-15；业务规则以指南和[需求](../requirements.md)为准。
进度与证据只见[实施计划 §14：本轮本地最终验收](../implementation-plan.md#本轮本地最终验收)。

基础交付模型由 `0114_service_delivery` 引入，`0115_service_revocation_evidence`
追加删除请求及最终计量证据的持久化时间。不为历史记录补造证据，不修改已有迁移。
[独立服务模型](independent-services.md)负责账号及服务归属，[权益与计量契约](entitlement-metering-contract.md)
负责用量、周期和限额；本页只说明两者如何参与交付。

## 接口与流程

- `GET /api/services/{service_id}/subscription`：仅允许当前所属账号，其他账号返回 404；
  封禁、暂停、耗尽、到期、待交付和未确认变更均不返回凭据。不读取账号旧身份，
  旧订阅路径继续 410。每次重新读取该服务的面板身份、归属标记、节点组、额度和到期。
  仅接受 HTTPS 链接，响应 `private, no-store`，服务列表不包含链接。
  必须是 `ready` 身份；激活前的 pending 准备检查不能代替此条件。新读取的累计用量
  使用共用观测函数保存；即使因耗尽或计数异常拒绝返回链接，也不丢弃该观测。
- 用户详情使用现有 `CopyLinkField`，按需加载本服务链接；关闭详情即销毁，不写浏览器
  存储，不记录返回的 URL。手动导入/更新说明只指向该份订阅，不自动选择其他服务。
- `POST /api/admin/services/{service_id}/deliver`：管理员提交账号、服务版本和幂等键。
  已准备身份、可用累计观测和专用资源核验齐备后，保存 `deliver` 操作记录及同步意图。
  worker 在所属账号锁内调用共用权益同步，确认禁用准备状态、条款和计量；只有
  共用同步成功、无待确认项且可交付时，才将 ready 与下一次同步标记一起提交。
  随后仍由共用权益入口决定是否启用。崩溃后可以重试，期间的暂停、封禁、到期与
  耗尽仍优先生效。重复请求不会更换身份、重置计数或新增额度。
- `POST /api/admin/services/{service_id}/revoke`：管理员提交账号、版本、幂等键和原因。
  保存取消决定及永久撤销意图后由现有身份 worker 重试；不修改额度或补发身份。
  查明归属、确认禁用后保存最后可读累计观测，再删除远端身份并重新查询不存在。
  首次读取及停用尚未生效时的读回也保留同一身份的计数；发现回退或重置即锁定异常，
  继续请求停用，但不能用后续较大数值绕过准确核对。
  异常计数保留待核对，不通过删除掩盖问题。最后观测先提交，避免 DELETE 后崩溃丢失。
  创建曾超时且尚未绑定 ID 时，空查询不能证明迟到创建已结束，撤销继续等待核对。
  暂停、封禁或到期后的准备重试也保留这份不确定性；迟到身份出现后仍绑定并撤销
  原身份，不能先降为“从未提交”再确认撤销。
  月度切点仍待确认时，使用 `settle_cancelled_service_period` 终止结算，操作者
  来自原撤销记录。保留旧周期和固定切点，记录切点后用量与未确认额度的审计，再清除
  待切换标记；不将冻结的上一周期页面用量称为最终用量，也不调用正常额度确认。
  删除前再次核对同一身份仍停用，将两次读取之间新增的字节通过共用观测保存并提交；
  首次结算审计是当时观测，最后累计以服务/连接持久化值为准。若出现新异常，停止删除。
  已绑定身份在首次读取前原因不明地消失，不能仅凭不存在就完成撤销。只有删除前已将
  停用后的最后计数与删除请求标记一起提交，后续不存在的重试才可作为删除确认。
  查询超时保留该证据；撤销、计量或权益任务再次读到实体都要求重新核对，不能复用先前
  标记掩盖新异常。删除前重新取得账号锁时，还需确认该证据未被其他任务清除。
  DELETE 后读回仍存在时同样清除旧删除证据：归属一致则保存新增计数或异常，归属不一致
  则记录冲突而不采纳他人的用量。之后仅查询到不存在不能绕过这次未确认的计量收尾。
  远端已不存在但仍有未结算切点、无效计数或已知计数回退/重置时，也不冒充已完成计量收尾。
  原因不明的消失继续显示待核对并保留原用量；本实现不提供估算用量、清零或自动换身份的恢复路径。
  面板确认不等于实际 Node 长连接已停止。历史保留取消原因与原条款，不能恢复该服务。
- `POST /api/admin/dedicated-exits/{exit_id}/verify`：提交资源版本、当前服务 ID（未分配为 null）、
  实际观察时间、出口 IP、固定/独享确认及证据。地址必须与库存一致。该操作是管理员
  记录实测证据，不是系统自动执行网络核验。
- `POST /api/admin/dedicated-exits/{exit_id}/reclaim`：同样携带版本和所属服务，要求身份已撤销，
  且实际停用与旧配置拒绝证据发生在撤销确认之后。仅此操作解除 IP 绑定；到期、暂停或
  面板返回成功均不会自动释放。释放后清除旧核验标记，新分配需要重新核验。
- `GET /api/admin/dedicated-exits/{exit_id}/audit`：分页管理员审计，保留原服务、操作人和证据。
  原账号删除不级联删除这些记录。证据中不得填写订阅 URL 或凭据。

分配、核验、回收使用资源行锁和版本；终止服务与账号操作使用所属账号行锁。
相同请求键返回原记录；不相同的请求内容拒绝。已回收请求的重放不会释放后续分配。
固定出口故障不自动改 IP、切共享线路或重新分配。更换由管理员人工核验与确认，
保留原绑定及停用／回收保护；更换确认同时申请恢复，重新检查原权益，不能解除主动暂停、封禁、到期或额度限制，也不能跳过计量／交付条件。
具体规则以[统一管理台指南 F07](../admin-console-guide.md#f07修改共享资源与常用节点操作)为准。

### 专用出口更换

`admin_console_exit_replacement_routes.py` 注册以下管理台接口，沿用管理员授权和 `private, no-store`：

| 方法与路径 | 职责 |
| --- | --- |
| GET `/api/admin/console/services/{service_id}/exit-replacement` | 查询更换阶段及当前状态。 |
| POST `/api/admin/console/services/{service_id}/exit-replacement` | 发起指定服务的更换操作。 |
| POST `/api/admin/console/services/{service_id}/exit-replacement/evidence` | 提交与当前操作关联的核验证据。 |
| POST `/api/admin/console/services/{service_id}/exit-replacement/confirm` | 确认更换，同时申请按原权益恢复。 |

`service_exit_replacement*` 负责更换编排与资源核对，恢复继续调用既有权益同步。
资源切换、恢复申请和实际恢复结果分别呈现；接口受理不能作为公网固定独享或连接恢复的证明。
通知与费用调整规则仍由需求文档保留为待定，不由更换流程自行补齐。

## 共用依赖与职责

交付层使用 `panel_traffic_limit`、带 `connection` 的 `matches_service_terms`、
`service_ready_for_delivery` 和 `synchronize_service_entitlement_locked`。
pending 到 ready 除共用同步成功，还要求 `sync_pending == False` 与可交付条件通过；
布尔成功可能只表示身份已安全停用，不能单独作为 ready 的依据。

月度累计限额与固定检查点由权益／计量模块统一计算；交付层不清零计数、不换身份补额度。
取消后的准确核对及终止结算使用同一观测模型。管理入口通过 `serviceChangeActions`
决定可用动作：已取消服务仅在计量异常且身份未撤销时提供准确核对，不提供恢复或续期。

## 本地验证记录

本页不登记分包测试数字或环境完成状态。实际结果见[实施计划 §14](../implementation-plan.md#本轮本地最终验收)，
旧检查点由[历史索引](../archive/index.md)定位。面板状态、真实连接、订阅客户端及公网独享出口分别取证，
不能以其中一项通过替代其他项；Node 的精确断连能力须按实际镜像、协议和同源场景核验。

定向回归在隔离工作区使用项目 `.venv/bin/python`：

```sh
.venv/bin/python -m pytest -q tests/unit/test_service_delivery.py tests/unit/test_service_provisioning.py --no-cov
npm --prefix frontend run test:e2e -- service-delivery.spec.ts
```

重点覆盖凭据按需读取、请求重放、远端写后崩溃、期间权益变更、计数异常阻止删除、
末次观测持久化、资源回收重放保护，以及桌面／手机菜单与对话框。
数据库和真实节点场景必须使用[项目隔离环境](project-local.md)并协调资源写入时段。
完整门禁按[贡献指南](../../CONTRIBUTING.md)选择，条件跳过不计为实际环境通过。
