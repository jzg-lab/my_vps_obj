# 管理员日常操作

本手册按实际任务组织，入口和按钮以仓库路由、组件及简体中文基础文案为依据。管理员在同一网站用同一账号管理客户和节点；一期人工开通，不接支付。完整入口表见[统一管理后台](../features/admin-panel.md)，新接手先读[接手指南](../handoff.md)。

这里不登记实施进度或测试结果。使用前从[实施计划 §14：本轮本地最终验收](../implementation-plan.md#本轮本地最终验收)确认环境、执行层和未验收范围；本地管理台完成不能推定生产已全部部署。页面未提供的操作不能靠猜测 URL 或修改数据库补做。

## 1. 进入管理台并找到对象

1. 在普通网站登录，使用“管理后台”入口；运行总览为 `/admin/console-overview`。后台资格来自当前账号的 `owner`／`admin` 角色，与登录渠道无关。
2. 客户问题从“客户 → 用户”（`/admin/users`）开始；按名称、邮箱或 ID 查找，核对账号后进入详情。这里的“用户”就是管理主线中的客户账号。
3. 已知服务问题可从“客户 → 全部服务”（`/admin/services`）开始，搜索并按状态筛选；“7 天内到期”的口径是未来 7 天。服务详情通过列表打开，地址使用 `service_id` 查询参数，不另造 `/admin/services/<id>` 页面。
4. 节点问题从“节点 → 节点”（`/admin/nodes`）开始，先核对稳定 ID、来源及读取时间，再看关联服务。不要用显示名称推断节点归属。

同一客户多份服务分别有自己的服务 ID、连接身份、用量、有效期和订阅。服务状态、执行进度及实际连接证据是三件事，必须分别看。

<a id="套餐与开通"></a>

## 2. 配置套餐并为客户开通

1. 打开“客户 → 套餐模板”（`/admin/service-plans`），用“新建套餐”或“编辑套餐”设置资源类型、资源范围、总流量／月度额度、有效期和价格。具体数值由管理员决定，不按名称猜测条款。
2. 到目标客户详情的“独立服务”区域点击“开通服务”，选择已有模板。专用 IP 类型还需选择符合条件的空闲出口。
3. 阅读“开通预检”：区分本地是否允许创建、资源观测是否就绪，以及身份与计量是否仍待准备。预检只读、不预留出口；“允许创建待交付服务记录”不是交付成功。
4. 条件变化时用“刷新模板与出口”重新选择核对，再提交“开通服务”。记录返回的服务 ID；结果未知时先刷新核对原请求，不新建第二份服务代替重试。
5. 服务登记后查看身份准备、用量核对和交付状态。满足条件时才出现“交付连接”；确认后继续查看该服务的“诊断与操作记录”，直至相应结果得到确认。
6. 客户在“我的套餐 → 我的服务”中打开该服务详情，通过“导入订阅”取得本服务链接，按[客户端教程](clients-zh.md)导入。不要代发旧账号级订阅或其他服务的链接。

创建模板不创建用户服务；再次开通同一模板会新增独立服务。价格是开通条款，不是收款回执。

修改模板额度按已确认规则影响同模板已开通服务的当前和未来额度，保留已用量并追加记录；价格、有效期、资源范围等其他条款保留服务原快照。共享组或 Host 本身的变更则可能影响存量服务，必须走下文资源影响预览。

## 3. 续期、暂停、恢复或撤销一份服务

从客户详情或全部服务列表选中**具体服务 ID**，打开“管理服务”。操作选项由当前状态决定，不能假设所有按钮一直可用。

| 任务 | 页面操作与核对重点 |
| --- | --- |
| 续期 | 选择“续期服务”，填写增加天数及记录价格等要求。起点为当前时间与原到期时间中较晚者；不清零用量，不改变月度锚点，也不取消暂停。 |
| 暂停 | 选择“暂停服务”，提交后跟踪业务目标与远端执行。账号级封禁不是暂停单服务的替代品。 |
| 恢复 | 选择“恢复服务”，仍受账号封禁、到期、额度、计量及资源条件约束；点击成功不代表连接已恢复。 |
| 核对用量 | 仅处理计数异常。按“核对用量”要求提供准确的跨周期累计字节、面板计数及依据；须满足暂停／取消和面板确认停用条件，不估算、不清零、不重建身份。核对本身不解除暂停／取消。 |
| 撤销 | 使用独立的“撤销服务”入口，填写原因并确认不可恢复。专用出口不会随撤销自动释放。 |

服务内“查看历史”核对开通与权益变更，“诊断与操作记录”核对执行过程。响应丢失先查看原记录；出现“核对上次提交”时沿原请求查询，不重复发放权益。

账号封禁／解封针对整个账号。删除账号前须确认各服务连接撤销、专用出口已人工回收；删除后从“服务历史”查询归档，不把归档记录重新当成可用权益。

## 4. 排查客户无法连接

1. 核对客户账号及所用服务 ID，确认客户端没有选到另一份配置。
2. 看账号封禁、服务暂停／取消、有效期、已确认用量与额度；日期为北京时间，月度切换提示不能当作用量清零。
3. 打开“诊断与操作记录”，对照本地业务记录、目标权限、远端观测、身份归属、权益匹配和计量异常。来源失败或未知保持未知。
4. 查看“服务资源关系”，沿 Node、Host 和组进入资源详情。授权关联表示潜在范围，不证明客户当前连接到了该节点。
5. 只有服务端允许时才使用“重试既有意图”。受理表示进入核对流程，不会续期或清零用量；继续刷新权威记录确认结果。
6. 客户端问题记录系统、客户端版本、服务 ID、时间、脱敏错误及复现步骤，按[客户端故障核对](clients-zh.md#4-更新与故障核对)处理；需要沟通时使用[客服工单](../features/support.md)。

面板读取正常不能证明代理通路正常，也不能证明旧连接已经停止。精准断连须遵守实施计划记录的版本与协议边界：固定本地 r3 forward VLESS 的证据不能外推到默认 Node；默认镜像仍保留同源 IP 下误断另一服务的风险。

## 5. 从节点查看影响范围

在“已纳管节点”清单打开节点详情，核对 Node ID、管理状态、配置档案、入站、Host、授权组和观测来源。查看“潜在关联服务与客户”，按服务进入详情，按客户进入账号；一个客户的多份服务不能重复计为多人。

节点流量窗口为“今天（UTC）”“含今天的近 7 个自然日（UTC）”“含今天的近 30 个自然日（UTC）”，与服务额度的北京时间月度周期不同。面板在线身份数不是去重客户或设备数，网卡 RX/TX 不是服务计费流量。没有样本、采样时间或代理延迟／丢包证据时，不用零值或管理请求耗时替代。详见[状态与指标口径](../features/server-status.md)。

## 6. 修改节点、授权组或线路

1. Node 操作从节点详情的“预览资源影响”进入，选择页面提供的启用、停用或重启操作。组与 Host 从“节点组与线路”（`/admin/node-resources`）详情的“预览组草稿”或“预览 Host 草稿”进入。
2. 填写实际变更并点击“读取影响预览”。核对当前值、拟议值、直接授权影响、可能重载影响、去重客户和服务、阻断原因及恢复办法。
3. 核对预览版本后勾选确认；“重新核对预览”仍是只读。来源不完整、范围变化或写入保护未解除时，先处理提示，不沿用过期确认。
4. 仅当页面显示可执行且条件满足时，点击“确认并提交操作”。提交会再核对范围并登记操作；回执不是客户端连接测试。
5. 点击“查看操作记录”，核对配置读回、重载受理、身份关联、执行结果及范围保护。结果未知时用“续查原提交”或记录中允许的“读回并核对”，不要新建重复操作。
6. 若记录提供“预览重试”或“预览恢复前值”，先重新预览再确认。创建不自动删除回滚；外部已删除的目标必须按原精确 ID、完整新鲜清单和原请求已终止证据人工核对，不能按同名资源认领，也不能把解除保护当作服务恢复。

资源修改可以影响已有服务，但必须先展示范围并明确确认。客户通知与费用调整规则尚未确定，本操作不会因此获得对外通知或财务处理授权。

## 7. 登记待接入节点或实际接入 Node

这两条路径处理不同对象：

| 路径 | 实际作用 |
| --- | --- |
| 节点 → 待接入节点 → 登记待接入节点 | 只保存名称、地址、备注。地址为 IPv4、IPv6 或 ASCII 主机名，不含 URL、端口、凭据；备注不存密码或私钥。 |
| 编辑记录／删除本地记录 | 只改本地待接入清单，不探测、安装、连接或删除服务器，不改变已纳管资源。名称／地址相同也不自动认领。 |
| 已纳管节点页的“登记节点” | 针对实际 Remnawave Node 资源，通过草稿、影响预览及确认登记操作。与待接入本地记录不同。 |
| “部署引导 → 生成部署配置” | 生成敏感配置，不执行 SSH 或安装。关闭后清除弹窗内凭据；实际部署需另行明确目标、影响和回退。 |

登记实际 Node 前，须已有可用配置档案（Profile）和入站；缺少时先通过高级维护准备，再回到接入向导选择。接入后按“登记阶段 → 管理连通阶段 → 订阅验证阶段”分别核对。配置 Host 与授权组，再用获准的隔离服务验证订阅、实际连接、计量和未授权访问，不能用登记成功或管理在线代替。

部署引导的标准 Node 镜像不包含 r3 精准断连适配，不能因获得配置就判定执行层验收完成。现用 3x-ui 也不是已部署的 Remnawave Node；接入或改动现用机器需单独安排。

## 8. 专用出口分配、更换与回收

从“节点 → 专用出口”（`/admin/dedicated-exits`）登记资源并按页面提交真实核验证据。资源名称或 IP 字段不证明固定、独享或实际出口；公网固定独享验收边界见实施计划。

开通专用服务时选择符合模板条件且可用的出口，绑定后核对实际交付。出口到期或服务撤销后保留占用，确认连接已停用后由管理员回收；不能仅解绑数据库就交给另一客户。

故障更换从指定服务的“更换专用出口”进入，按页面核对候选资源、旧访问停用证据和新出口证据，区分机器观测与管理员声明。确认更换同时申请按原权益恢复，无需另一次恢复确认；封禁、主动暂停、到期、额度及计量限制仍有效。分别看资源切换、恢复申请和实际结果，禁止自动改成共享出口，旧资源不因申请恢复而自动释放。

## 9. 查询记录或进入高级维护

| 要回答的问题 | 入口 |
| --- | --- |
| 这份服务当时按什么条款开通、后来改了什么？ | 服务内“查看历史”。 |
| 哪次执行失败、是否允许重试？ | 服务内“诊断与操作记录”，或 `/admin/console-operations` 的服务记录。 |
| 共享资源操作是否执行、保护是否解除？ | 同一“服务操作”页选择“资源操作记录”，也可从资源页跳转。 |
| 谁封禁／解封了账号、意图是否被后续操作替代？ | 同页选择“账号操作记录”；不与服务订单混计。 |
| 删除账号后保留了什么？ | `/admin/service-history`；归档记录不等于活跃账号或连接权限。 |
| 低频原始协议或复杂配置如何维护？ | `/admin/advanced-maintenance`；仅显式安全 `PANEL_PUBLIC_URL` 可提供外部入口，不携带管理凭据，不承诺 SSO。 |

空记录不证明服务正常，日志也不代替执行回执。高级维护不另建一套权益账；外部变更后回到本项目核对业务目标和远端观测。
