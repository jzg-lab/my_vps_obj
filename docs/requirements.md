# 我的 VPN｜需求基线

版本：v0.21（节点国家与本地显示标注）

日期：2026-10-28（北京时间）

配套文档：[统一管理台实施指南](admin-console-guide.md) · [产品设计](product-design.md) · [架构决策](architecture-assessment.md) · [实施与验收](implementation-plan.md)

本文记录用户已经明确的需求，供网站、运营后台、节点管理和未来自有 App 共同对齐。它描述产品必须达到的结果，不代表当前部署已经具备这些能力。

文档状态分为三类：**已确认**是用户明确表达的要求；**建议**是尚待用户决定的方案；**待定**是不能由开发者自行补齐的业务规则。配套产品设计不能覆盖本文中的已确认要求。

## 1. 产品要解决什么

为当前十几位朋友提供容易使用的网络服务，并保留未来增长空间。用户使用自己的账号，可以同时拥有多个套餐，获得各套餐允许使用的节点，并在通用客户端或未来自有 App 中使用。

**已确认的分阶段人群：**一期优先服务已经会使用订阅服务（俗称“机场”）、导入订阅和使用通用客户端的人，先完成网站、运营后台和通用客户端接入。后续自有 App 主要面向不会配置和使用这类服务的人，降低连接使用门槛；自有 App 不在一期交付范围内。

产品核心是一个管理员可自由配置的套餐系统。资源类型、流量计算方式、流量额度、有效期和价格都是套餐配置；管理员可以创建不同组合的套餐，并向有需要的用户分配固定、专用的出口 IP。具体数值由管理员录入，不需要在设计阶段逐款确定。用户不需要理解节点部署、资源分配等实现细节。

一期以 MVP 为目标，**暂不接支付**。长期仍希望支持自助购买和续费，但不因此提前增加一期复杂度。

## 2. 术语

| 名称 | 本文含义 |
| --- | --- |
| 账号 | 一个人登录网站和未来 App 的身份。一个账号可以拥有多份服务。 |
| 套餐类型 | 当前确认支持“多节点订阅”和“单人单 IP”两种，决定这份套餐如何提供连接资源。 |
| 套餐模板 | 管理员创建的产品定义：资源类型、名称、资源范围、流量计算方式、额度、有效期和价格等。同一种类型可以创建多种套餐。 |
| 流量／计费规则 | 按配置的总流量包定价，或按订阅时长定价并设置每月流量额度。规则与资源类型分开配置。 |
| 已开通套餐／服务 | 某个用户实际获得的一份权益，有自己的状态、用量和到期时间。不同于套餐模板。 |
| 节点组 | 一组允许使用的节点，例如普通线路组、三网优化线路组。 |
| 订阅链接 | 客户端获取连接配置的凭据，含用户敏感信息，不得公开。与业务上的“购买一个套餐”不是同一概念。 |
| 专用出口 IP | 分配给某个用户使用的固定出口地址，目标是该出口不与其他用户共用。 |

## 3. 已确认需求

| 编号 | 要求 | 具体含义 |
| --- | --- | --- |
| R01 | 每人独立账号 | 用户分别登录、查看和使用自己的服务。 |
| R02 | 管理员创建并配置套餐 | 创建时选择“多节点订阅”或“单人单 IP”资源类型，再配置名称、资源范围、流量规则、流量额度、有效期及价格。上述数值由管理员自由设置；普通、三网优化等只是示例，不是系统固定套餐。 |
| R03 | 一个账号可以同时拥有多个套餐 | 用户可以同时拥有管理员配置的多份套餐，支持两种类型并存，不能强制只能保留一份当前套餐，也不固定为三份。 |
| R04 | 各套餐独立计算权益 | 每份已开通套餐分别计算流量、有效期和状态。一份用完或到期，不应耗尽或终止另一份仍有效的套餐。 |
| R05 | 同一套餐内跨节点共用额度 | 使用这份套餐中的不同节点，都扣这份套餐的额度；切换节点不会获得一份新额度。 |
| R06 | 多节点订阅按配置授予节点权限 | 管理员选择该套餐可使用的节点或节点组，用户只能使用获授权的节点。“普通”“三网优化”等分组如何组合由管理员配置，不由套餐名称或代码写死。 |
| R07 | 单人单 IP 类型按用户交付专用出口 | 每份已开通的单人单 IP 服务向该用户分配一个固定专用出口 IP，单独计量、单独到期，并能在“我的服务”中查看。同一套餐模板可供不同用户开通，但不能让他们共用同一个专用出口。固定性与独享必须依据实际资源和连接证据核验。 |
| R08 | 保留通用客户端使用方式 | 用户可以获取、导入和更新自己的订阅，并选择获授权节点连接。不能要求所有用户只能使用自有 App。 |
| R09 | 保留现有页面风格和基本交互 | 用户喜欢现站界面，当前主要问题是客户端推荐陌生、教程不够直白。多套餐展示所需的局部调整可以另行设计。 |
| R10 | 改善客户端推荐与中文教程 | 每类设备目标提供 3～4 款合适客户端，配官方下载链接、中文安装与导入步骤。电视端按实际兼容情况列出，不为凑数量推荐软件。 |
| R11 | 网站与未来 App 共用业务记录 | 共用账号、已开通套餐、流量、有效期和后续订单权益，避免分别维护两套账。自有 App 已确认放到后续交付。 |
| R12 | 一期不接在线支付 | 一期支持套餐价格配置，但暂不接在线收款、自动扣费或支付渠道申请。价格与订单规则不等于接入支付。长期自助购买与续费目标保留。 |
| R13 | 一期由运营者在后台直接开通 | 运营者直接为用户开通套餐。一期不需要用户提交申请的页面。 |
| R14 | 套餐支持两种流量／定价方式 | 可按总流量包设置价格，也可按订阅时长设置价格并配置每月流量额度。两种方式下的额度、有效期、价格均由管理员配置，不把流量包默认写死为永久有效，也不把月流量额度当作整份订阅的总额度。 |
| R15 | 分阶段服务不同使用经验的用户 | 一期通过网站和通用客户端服务会使用订阅的用户；后续自有 App 主要服务不会配置和使用订阅的用户，降低使用门槛。 |
| R16 | 服务端限额，优先使用体验 | 按上传＋下载的业务流量计量，不含网络协议开销。同一服务跨节点汇总，确认额度耗尽或到期后执行停用，尽量减少超额。用户已撤回绝对零超额要求，优先保证使用体验；具体统计与停用延迟须实测。 |
| R17 | 一期支持简体中文 | 用户网站与本项目运营后台可使用简体中文，覆盖一期实际开放页面、表单、状态、错误提示、弹窗和使用说明；中文阅读路径的文档正文、导航及提示也须为中文，不能只翻译导航或教程。复用现有多语言能力，保留英文、俄文基础语言与俄语选项。 |
| R18 | 同一网站与账号进入统一管理台 | 管理员从正常网站进入管理控制台，并能返回用户视角；日常管理使用现有业务账号与权限，普通客户不获得管理权限。 |
| R19 | 以客户与节点为两条管理主线 | 客户、独立服务、节点与资源可双向追溯；管理员能从客户定位服务和资源，也能从节点查潜在影响客户。授权范围与当前连接分别展示。 |
| R20 | 提供可信的运行指标 | 管理台展示客户与服务、节点运行、交付同步和出口库存，指标有明确口径、来源与更新时间，异常可进入具体处理页面；未知、过期或失败不能显示成零或正常。 |
| R21 | 日常操作与节点接入形成完整流程 | 开通、续期、暂停、恢复、交付重试、出口操作和常见排障在本项目完成；分批纳入节点接入、验证及组与线路常用管理。底层继续使用 Remnawave，低频原始协议、复杂路由等保留高级维护入口。 |
| R22 | 后续更新遵循统一管理台指南 | 页面职责、流程、指标、整合边界与专项验收以统一管理台实施指南为执行依据；进度与证据在实施计划维护。新决定同步文档，不能以方案确认代替功能实现。 |
| R23 | 节点信息可读且来源明确 | 国家使用 Remnawave `countryCode`（按界面语言显示，不从地址或名称推断）；管理员可按稳定 Node UUID 在本项目维护显示名、地区／城市和网络服务商，作为本地标注，不修改 Remnawave 或节点配置。 |

R18～R22 于 2026-10-24 经用户确认。详细实施规格见[统一管理台实施指南](admin-console-guide.md)，不改变 R01～R17 及已经确认的服务规则，不默认授权迁移现用节点。

**共享资源变更规则（2026-10-24）：**节点组成员或线路变更允许影响已有服务，但执行前必须展示受影响客户与服务清单，由管理员确认；执行时重新核对范围。修改模板的资源范围仍只影响后续开通，不覆盖既有服务快照。

### 套餐类型、套餐模板与用户开通的区别

管理员先创建套餐模板，并选择类型：

| 类型 | 管理员配置什么 | 开通后用户获得什么 |
| --- | --- | --- |
| 多节点订阅 | 套餐名称、可用节点／节点组、额度和周期 | 一份可导入客户端的节点订阅，在获授权节点之间选择使用，共用该套餐额度。 |
| 单人单 IP | 套餐名称、额度、周期及可交付的专用出口资源条件 | 分配给该用户的一个固定专用出口，按这份套餐单独计量和到期。 |

例如，管理员可以把多节点订阅配置为“普通线路”“三网优化”或其他组合，也可以创建多个不同地区或条件的单人单 IP 套餐。这些都是录入的套餐内容，不是开发者预设的产品名单。

创建套餐模板不等于立即给用户开通，也不等于把同一个 IP 固定写进模板供所有人共用。一期由管理员选择账号与已有套餐模板，再开通一份属于该用户的服务。

### 统一套餐配置

所有产品本质上都是套餐，不为“流量包”“月度套餐”分别建立互不相干的产品系统：

| 配置维度 | 管理员设置的内容 |
| --- | --- |
| 资源类型 | 多节点订阅，或单人单 IP。 |
| 资源范围 | 可用节点／节点组，或专用出口资源条件。 |
| 流量规则 | 一份套餐总共可用多少流量，或订阅有效期间每月可用多少流量。 |
| 有效期 | 由管理员设置，不按套餐名称或资源类型写死。 |
| 价格 | 由管理员设置对应套餐规格的价格。 |

套餐配置描述“提供什么、有什么限制、卖多少钱”；开通及操作记录描述“为谁、按什么条件执行了什么”；用户服务记录实际权益。三者不能混为一条会随模板改动而变化的记录。人工开通保留价格和条款快照，不等于已经在线收款，不因此提前接入支付。

**已确认的额度调整例外（2026-10-23）：**管理员修改套餐模板的流量额度时，同模板已开通服务统一调整，影响当前及未来周期，已用流量不清零。其他条款（价格、有效期、资源范围等）保留原始快照；原开通记录与已结算历史不改写，额度变更另留记录。删除账号后脱离账号的归档历史仍保留，不重新授予权益。调整额度不能绕过暂停、封禁、到期或已撤销状态。

按月额度需要区分订阅整体有效期与月度额度周期。每月额度用完不代表订阅已经到期；下个周期能否继续使用取决于订阅是否仍有效及配置规则。已确认：以开通时刻为锚点，按北京时间的日历月计算周期；遇月底取当月最后一天，后续月份仍使用原始开通日。每周期恢复配置额度，余量不结转，不采用固定 30 天周期。

单人单 IP 存在持续资源占用成本，管理员定价和有效期配置需要覆盖实际成本；这不改变有效期和价格由管理员决定的要求。

### 流量独立的例子

假设管理员创建了普通套餐 A 和优化套餐 B，用户甲同时拥有这两份套餐。使用 A 的任意获授权节点，扣 A 的额度；使用 B 的节点，扣 B 的额度。A 用完后停止 A 的使用，B 在自身仍有效且有额度时继续可用。A、B 仅作说明，不限定实际套餐名称和数量。

这是两个独立套餐，不能用“一份套餐里展示两个节点分组”代替，除非它同时满足各自计量、各自到期和各自停用的全部要求。

### 专用出口的边界

用户当前确认的需求是：**使用这项服务时，获得属于自己的固定专用网络出口。**

- “固定”指正常服务期间保持已分配的出口。专用出口故障时保持异常，由管理员核验新出口后手动确认更换，禁止自动切换共享出口。更换确认同时申请恢复，执行时重新检查封禁、主动暂停、到期、额度及既有计量／交付条件，权益允许才恢复；不另行要求恢复确认，不借更换解除限制。通知、费用调整及供应商主动变更规则仍待定。
- “专用”需要实际资源支持和分配验证，不能只通过节点改名或前台显示一个 IP 来实现。
- 已确认一期允许普通机房公网 IP，只要固定且不与其他用户共用；住宅属性不是硬要求，地区后续按实际资源配置。
- 不要求整台物理机或服务器只服务一个人。
- 不包含独立浏览器、Cookie 隔离、远程桌面或设备环境隔离。
- 固定专用 IP 本身不构成对 Claude 等第三方服务可用性的保证。
- 是否让全部设备流量都经过该出口、还是只对指定连接生效，属于后续使用方式设计，不能自行扩大范围。

**首页布局确认（2026-10-23）：**保留原有简洁品牌概览，“我的套餐”设为独立导航入口，内含已开通套餐和套餐目录，不在首页常驻一列套餐卡片。多套餐独立计量、独立订阅和人工开通规则不变。

## 4. 一期范围与未定事项

### 一期产品核心

围绕独立账号、多套餐并存、套餐独立额度与有效期、节点权限、通用客户端导入、简体中文界面及中文教程完成 MVP。专用出口是已确认的产品能力方向，其一期交付范围取决于资源可得性和用户确认，不能擅自删除，也不能承诺现有机器已能提供。

**已确认的一期客户端范围：**接入通用客户端，不开发自有 App。优先让熟悉订阅的用户实际用上，仍保留已确认的中文教程与官方下载链接要求。

**已确认的一期交付方式：**由运营者在后台直接为用户开通套餐，用户在网站查看与使用，不开发申请页面。专用出口作为独立套餐开通；人工续期、已有出口分配与回收按第 7 节及管理台指南执行。

### 不作为本次需求的默认附加项

- 支付接入、自动扣费、自动退款。
- 自动购买或自动创建服务器、住宅线路、专用 IP。
- 独立浏览器环境、指纹管理、远程桌面。
- 重做整站视觉、强制迁移技术栈、强制使用自有 App。
- 分销、邀请奖励、复杂营销和其他未明确提出的商业功能。

这些功能若后续需要，应单独确认，不因现有系统带有相关功能而自动纳入一期。

## 5. 当前系统与需求的关系

本项目在 `my_vps_obj` 仓库维护业务网站与管理台，基于 Minishop v3.8.2 二次开发，保留 Remnawave 控制和执行层。准确版本与部署范围查看[环境记录](development/project-local.md)，实现及验收查看[实施计划](implementation-plan.md)。

初始源码评估发现：上游常规流程围绕一个主要连接身份和一份当前订阅组织，单靠配置不能满足 R03、R04。数据库可保存历史记录、普通／premium 两类额度或套餐切换，都不能替代多份独立服务。初始调查保存在[历史架构评估](archive/architecture-assessment-20261024.md)。

**已采纳方向：基于 Minishop 二开，统一改造服务业务。** 账号、权限和页面基础继续复用；每份服务的身份、计量、交付和账号生命周期由本项目统一处理。插件接口按需使用，不作为完整多服务生命周期的替代。技术职责见[架构决策](architecture-assessment.md)和[独立服务模型](development/independent-services.md)。

二开仍需承担上游升级、回归与数据迁移成本。统一产品不等于合并业务库与面板库，也不默认授权改动现用节点。上游单订阅说明归入[兼容参考](upstream/index.md)，不能作为本项目的默认开通流程。

| A01 | 同一账号开通普通与优化两份套餐 | 两份同时存在，分别显示额度、用量、到期时间。 |

| A03 | 普通套餐用完或到期 | 普通套餐不可继续使用，仍有效的优化套餐不受影响。 |
| A04 | 用户尝试访问管理员未配置给其套餐的节点 | 服务端拒绝未授权连接；仅在网站隐藏节点不算通过。 |
| A05 | 两份服务同时产生流量 | 用量分别归属正确，不因共用账号而混记或重复扣减。 |
| A06 | 使用专用出口服务，并断开后重新连接 | 正常情况下出口保持为已分配地址，资源记录与实际出口一致。 |
| A07 | 不同用户使用专用出口服务 | 不重复分配仍在使用的同一专用出口；核实资源供应方的独占条件。 |
| A08 | 向同一账号增加或续期一份套餐 | 不覆盖其他套餐、不重置其他套餐的用量或有效期。 |
| A09 | 通过选定的通用客户端导入订阅 | 获得正确服务的配置；更新订阅后权限与服务端一致。 |
| A10 | 将来网站和自有 App 同时接入 | 两端读取相同权益，停用、续期和用量变化能够一致反映。 |
| A11 | 管理员为用户开通普通、优化和专用出口三份套餐 | 不依赖付款或申请记录，三份服务独立生效，专用出口仍需实际资源就绪后交付。 |
| A12 | 管理员创建不同名称、节点组合、额度和周期的套餐 | 在后台选择两种类型并完成配置，不需要修改代码来新增某个具体套餐；用户看到相应配置。 |
| A13 | 给两名用户分别开通同一个单人单 IP 套餐模板 | 各自获得独立服务和不同的专用出口资源，不能因模板相同而共用一个 IP。 |
| A14 | 管理员分别创建总流量包和按月额度套餐 | 可自行设置额度、有效期和价格，用户看到并获得对应配置；不需要修改代码或写死套餐名单。 |
| A15 | 月度额度耗尽后进入下一个配置周期 | 在订阅仍有效时按规则恢复该周期额度，不改变总到期时间、不影响其他套餐；总流量包不会因此自动补满。 |
| A16 | 同一服务在多节点并发使用并接近额度边界 | 正确汇总上传＋下载业务流量，确认耗尽后停止该服务，记录实际超额量与停用延迟；不能通过截断页面数值隐藏超额。 |
| A17 | 节点重启、断连、重试、周期切换或恢复备份 | 不因重试、计数回退或恢复旧记录重复发放权益；暂时统计失败不能被误判为额度耗尽，也不能把用量清零或重置额度。 |
| A18 | 以简体中文完成用户和管理员的一期流程 | 登录、套餐浏览、服务详情、订阅教程，以及后台套餐配置、开通、服务管理、资源与历史页面均有简体中文；错误与确认提示不遗漏，切换语言和刷新正常，桌面及手机布局可用。中文阅读路径中的文档正文、导航与提示均为中文，不以俄文或只翻译目录代替；俄语选项保留。 |
| A19 | 修改套餐模板额度 | 同模板已开通服务的当前和未来额度统一调整，已用量不清零；其他模板、原始价格/到期/资源快照和已结算历史不变，变更有记录且重试不重复发放。 |
| A20 | 持续流量中切换月度，或写入后响应丢失/数据库提交失败 | 以已持久化的同一个累计检查点为切点，后续流量归新周期；重试不移动切点或重复发额度，不要求计数停止增长，页面核对成功后展示新周期。 |
| A21 | 计数被重置且部分用量缺失 | 保留已确认用量和异常，只有查清准确数字并留存核对依据后才恢复正常计量；不以估算、清零或新建身份替代核对。 |
| A22 | 管理员在正常网站进入管理台，普通用户直接访问管理接口 | 管理员使用同一账号完成切换，普通用户被服务端拒绝；角色撤销后也不能继续获得管理能力。 |
| A23 | 从客户查询服务与节点，再从节点查询相关客户 | 关系明确且可双向进入详情；潜在影响按账号去重，授权关系不冒充当前连接或实际故障影响。 |
| A24 | 查看运行指标，发生采集失败或返回部分数据 | 指标口径、来源、时间和完整性明确；客户、服务、身份与连接不混计，未知不补零，卡片可进入一致的明细。 |
| A25 | 在统一管理台完成日常服务管理与故障处理 | 不需要跳转外部后台手工对账或修改权益；能跟踪实际执行结果，失败可核对恢复且不重复发放权益。 |
| A26 | 接入节点、设置线路与组并供套餐使用 | 登记、接入和实际使用验证区分；资源变更展示影响范围，不静默改变存量服务权益。 |
| A27 | 后续更新客户、节点、指标或后台流程 | 对齐指南中的工作包、流程与 UA 验收项，记录实现和验证证据，不把只读展示或外部链接当成全部整合完成。 |

A22～A27 的详细场景见[统一管理台实施指南](admin-console-guide.md)第 11 节 UA-01～UA-20。

A10 属于 App 对接时的验收。最新决定为体验优先、尽量控制超额，替代此前的严格零超额要求。业务流量与服务器网卡账单不是同一口径；长期统计故障的处置与可达到的超额控制指标在实现和联调时明确，不能解释为无限量使用。

## 7. 已确认的服务规则

- 月度边界按北京时间（Asia/Shanghai）计算，以开通时间为原始锚点。1 月 31 日开通，下一次取 2 月最后一天，再下一次恢复到 3 月 31 日，时刻保持一致。
- 每周期恢复管理员配置的月度额度，未使用额度不结转；周期切换不延长服务总有效期。
- 月度切换采用固定检查点：先持久化累计用量切点，切点之后的流量算新周期；页面仍等远端核对成功后展示新周期。重试沿用同一切点，不因持续流量再次上调并重复发放额度，不主动中断正常连接。北京时间日历边界、原始开通锚点和不结转规则不变。本条为用户在 2026-10-23 确认的细化，替代此前“后台确认前全部流量归旧周期”的要求。
- 一个账号可以重复开通同一套餐，各份服务独立计量、独立订阅，不自动切换消费另一份服务。
- 续期只延长有效期，从原到期时间与当前时间中较晚者起算；不重置用量，流量调整单独记录，月度重置继续使用原开通锚点。
- 专用 IP 到期先保留绑定，由管理员确认连接已停用后手动回收；不能仅修改数据库绑定就允许再次交付。
- 本地验证、公网出口验证与生产节点操作分开安排。公网固定独享出口验证按用户 2026-10-24 的决定另行安排；已有连接或环境资料不自动授予新的生产操作权限。
- 删除账号时，先确认连接已撤销、专用 IP 已由管理员回收；删除登录账号，保留解除账号关联的服务及开通记录，用于核对历史额度、日期和价格。
- 修改模板额度统一影响同模板已开通服务的当前和未来周期，保留已用量；原开通快照与其他条款不覆盖，追加额度调整记录。
- 异常计量缺失历史必须查清准确数字后才能恢复，不允许管理员以估算数字代替准确核对；已有确认用量不丢弃。
- 待接入节点清单由管理员手工维护名称、地址和备注；登记、修改与删除只影响本地记录，不自动连接、探测、安装或匹配远端节点。

共享组变更及专用出口故障处理的已确认规则见第 3 节和管理台指南 F05～F07；技术实现与验收分别记录，不重复列为待定业务规则。

## 8. 待确认清单

以下业务选择仍需在对应工作前确认，不能默认为已获同意：

1. 新的周期、结转或续期方式；一期继续执行第 7 节，不能因上游支持其他方式自动增加。
2. 公网专用出口的实际地区、供应资源、数量与持续成本；允许机房公网 IP，不等于指定资源已经满足独享条件。
3. 故障通知渠道、客户通知和费用调整规则；人工更换、按权益申请恢复和手动回收已经确定。
4. 后续自有 App 的优先平台与具体操作流程；不阻塞一期通用客户端交付。
5. 长期统计／控制故障的业务处置，以及结合实测确定的停用延迟和超额控制目标。

套餐名称、额度、价格和资源组合由管理员录入，不逐款作为架构待决事项。接口字段、客户端兼容和资源核验属于技术核查／验收工作，按实施计划补证；不能混成未决定的业务规则。

## 9. 如何共同维护

- 后续讨论、方案评估和实现前，先阅读本文、统一管理台实施指南及配套产品设计。
- 用户新的明确决定优先；更新本文时记录日期、影响范围，并同步调整指南、产品设计和实施计划中的相关内容。
- 产品设计中的建议只有经过用户确认，才能提升为已确认需求。
- 技术方案若无法满足 R03、R04 等硬要求，应明确报告差距，不得静默将需求缩减成软件现有功能。
- 网站、后台和业务模型在本仓库共同维护；后续 App 共用业务记录，节点仍是独立运行组件。
- 文档不存放密码、密钥、真实订阅地址或用户私密信息。
