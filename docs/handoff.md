# 项目接手指南

面向新加入的开发者、窗口和智能体。先建立业务、代码和环境边界，再领取任务；不需要从历史聊天或上游安装说明开始猜测。

直接阅读仓库内的 Markdown 文件即可接手，不需要启动文档网站。根 `AGENTS.md` 是智能体入口，本文提供阅读顺序，[文档目录](index.md)提供分类索引。

## 1. 先理解这个项目

**我的 VPN** 是基于 Minishop 二次开发的业务网站和统一管理台。客户与节点是两条管理主线：管理员使用同一账号完成日常管理，客户使用自己的独立服务。

| 名称 | 含义 |
| --- | --- |
| 我的 VPN | 本项目的产品名称。 |
| `my_vpn` | 当前本机检出目录名称，不是部署标识。 |
| `my_vps_obj` | 本项目仓库名称。 |
| `my-vps-obj` | 隔离 Compose 项目及 Colima 配置使用的名称。 |
| Minishop | 本项目复用并修改的业务应用基础；上游单订阅业务不等于本项目独立服务。 |
| Remnawave Panel / Node | 控制面与节点执行层；保留独立运行，通过接口与本项目协作。 |

“统一”指统一账号、管理入口、业务记录和操作流程，不要求合并数据库、代理内核或所有运行进程。

## 3. 不得误解的业务规则

- 一个账号可以拥有多份服务，包括重复开通同一模板；身份、订阅、用量、有效期分别独立。
- 套餐模板、已开通服务和操作记录是不同对象。模板额度变更会按确认规则调整同模板既有服务，其他条款保留快照。
- 月度额度按北京时间、原始开通日计算，月底取当月最后一天；不结转、不采用固定 30 天。重试沿用已持久化切点。
- 上传加下载的业务载荷计入服务用量；网卡流量不是计费量。不承诺绝对零超额，不用清零或估算掩盖计量异常。
- 一期人工开通、不接在线支付、不开发申请页面或自有 App；上游支付、营销和单订阅说明是兼容参考。
- 共享组和线路变更须先预览客户与服务影响、管理员确认、执行时重新核对。
- 专用出口故障由管理员核验后更换，同时按原权益申请恢复；不绕过封禁、暂停、到期和额度，也不自动降为共享出口。
- 待接入清单只记录名称、地址和备注，不探测、安装或自动认领服务器。

完整规则以需求和指南为准；这里是接手时的防误读摘要。

## 4. 如何判断“做完了”

| 看到的材料 | 能说明什么 | 不能据此推断什么 |
| --- | --- | --- |
| 需求、设计、指南 | 必须满足的结果和约束 | 功能已实现或已上线。 |
| 代码、单测、演示页面 | 对应实现及受测行为 | 实际节点、真实出口或所有平台都通过。 |
| 第 14 节本地验收 | 指定源码、环境和场景的证据 | 同一版本已发布生产。 |
| 第 15 节及历史生产记录 | 某次明确范围的现场结果 | 其他批次代码已部署，或可以继续操作生产。 |
| 上游功能和兼容参考 | 原能力、参数及维护方式 | 本项目一期已经开放这些业务。 |

特别核对第 14 节的默认 Node 与隔离 r3 适配、公网独享出口、缺失指标、图形客户端及高负载边界。不要把“未采集”改成零，不要以配置页面成功冒充连接恢复。

## 6. 接到任务后怎么做

1. 明确用户可见目标、对应 UC／F／UA 及不在范围内的内容；维护性修改引用对应约束即可。
2. 查看工作树和其他执行者的文件范围，保留未提交改动，不覆盖别人的工作。
3. 查已有实现与实际调用方，确定唯一主改者；迁移、生命周期、共享组件和生成契约不能多人同时改。
4. 按贡献指南执行匹配的门禁，分开记录模拟、数据库、真实节点、客户端和生产证据。
5. 在实施计划第 14 节登记结果、证据及遗留项；新业务决定同步需求和指南。已有历史记录不是重新派发指令。

凭据不写入文档、日志或截图。生产连接资料保存在项目环境文档中；已有连接信息不等于任意部署授权。文档整理、代码审查和本地测试不需要连接生产。
