# 广告核查与限制

本地验证使用开发环境的模拟数据配置，会创建明确标记的演示活动。在独立浏览器检查网页链接、登录、优惠、下单和退款，对比首购／复购、外部付款／余额支付。

| 现象 | 检查内容 |
| --- | --- |
| 缺少 Telegram 链接 | Telegram 是否开启、机器人名称是否已获取 |
| 没有接触记录 | 活动是否有效、链接是否归档、是否使用了保留载荷 |
| 来源未知 | 接触是否早于下单且在归因窗口内 |
| 优惠不可用 | 有效期、次数、专属绑定及代码条件 |
| 导入被拒绝 | 列、ISO 日期、时区、币种、重复和区间重叠 |
| 多个候选 | 同一机器人在窗口内的其他启动；时间不能证明身份 |
| ROAS 缺失 | 是否有相同币种费用，以及是否选择费用来源 |

实施日志前的历史仍不完整，不能从付款 ID 猜测旧注册和成功时间。CSV 不修正已创建订单来源。删除账号后，接触中的个人关联匿名化，管理操作历史仍保留。匿名 cookie 在 30 天后停止关联访问。

浏览器演示与模拟数据不能证明具体 Telegram 客户端的 startapp 传递、外部 OAuth 或真实广告导出格式。发布广告前，应在测试机器人实际访问并验证自己的广告文件。

## 关闭新增入口

`ADVERTISING_ENABLED=false` 停止记录新广告接触和创建新结账快照。旧机器人链接仍填充原归因。新详情、导入和报表关闭；已有付款及退款继续更新，历史保留，旧活动列表仍可用。迁移不删除数据；回滚旧镜像应先在备份上验证。
