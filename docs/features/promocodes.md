# 激活码

本文属于[上游兼容参考](../upstream/index.md)，说明保留的激活码与历史链接能力。本项目一期不开放支付和营销购买流程，下文入口不作为独立服务的默认开通方式。

天数、流量和折扣规则作用于[上游单订阅销售模型](subscriptions.md)，不能直接套用到 `ServicePlan`／`UserService`。独立服务的规则见[额度与计量契约](../development/entitlement-metering-contract.md)，实现及验收范围只查[本轮本地最终验收](../implementation-plan.md#本轮本地最终验收)。

激活码在网页管理后台配置，可立即激活，也可在结账创建付款前使用。同一码可以组合兼容的固定奖励（天数、普通流量和 premium 流量），并搭配折扣或时长倍数。不兼容组合会被后台与 API 拒绝。

<a id="где-настраивать"></a>

## 配置入口

主要入口是网页后台“激活码”，支持：

- 手动输入代码，或留空由后端自动生成。
- 选择适用范围、效果、激活次数和有效期。
- 查看状态以及 Telegram 机器人、网页应用链接。
- 查看激活历史，包括付款、折扣金额、发放天数或 GB。
- 停用、编辑或删除代码。

Telegram 后台和批量创建保留为旧模式的快捷兼容流程，用于创建增加订阅天数的代码。折扣、倍数、适用范围和条件等新模式建议通过网页后台或管理 API 配置。

<a id="эффекты"></a>

## 效果

| 效果 | 行为 | 适用场景 |
| --- | --- | --- |
| 奖励天数 | 为按时长订阅增加天数，可立即发放或付款后发放。 | 按时长订阅。 |
| 普通流量，GB | 将固定流量加入持久保存的普通加购流量余额。 | 按时长订阅激活或付款。 |
| Premium 流量，GB | 将固定流量加入持久保存的 premium 余额；套餐必须包含 premium 节点组。 | 按时长订阅激活或付款。 |
| 百分比折扣 | 在创建付款前减少结账金额；Stars 最低保留 `1` Star。 | 订阅、流量包、普通／premium 流量加购、HWID 设备加购。 |
| 时长倍数 | 增加已购订阅时长，例如 `x2` 将 1 个月变为 2 个月。 | 按时长订阅。 |
| 流量倍数 | 增加发放 GB，例如 `x2` 将 100 GB 变为 200 GB。 | 流量包、普通和 premium 流量加购。 |

固定天数、普通和 premium 流量可互相组合，也可搭配折扣或时长倍数。固定奖励不能搭配流量倍数，因为发放规则不同。固定流量只支持 `all` 或 `subscription` 范围。

校验拒绝空效果、负值、超出 `0..100` 的折扣、低于 `1` 或超过配置上限的倍数。每个固定流量值精确到 `0.001` GB，范围为 `0.001..1000000` GB。倍数上限由 `PROMO_DURATION_MULTIPLIER_MAX`、`PROMO_TRAFFIC_MULTIPLIER_MAX` 设置。

<a id="области-применения"></a>

## 适用范围

| Scope | 覆盖场景 |
| --- | --- |
| `all` | 所有效果适用的购买。倍数建议选择精确范围，避免在不适用的结账中占用代码。 |
| `subscription` | 购买或续费按时长订阅。 |
| `traffic` | 购买按流量套餐或旧流量包。 |
| `traffic_topup` | 普通、premium 流量加购（`topup`、`premium_topup`）。 |
| `hwid` | HWID 设备加购，只支持折扣。 |

奖励天数和时长倍数应作用于订阅。流量倍数应作用于 `traffic` 或 `traffic_topup`。折扣可用于所有范围，包括 HWID。

<a id="мгновенная-активация-и-checkout"></a>

## 立即激活与结账

两种激活模式：

- **立即奖励：**只有固定天数和／或 GB，没有结账效果、`bonus_requires_payment` 或最低购买条件。用户在 Telegram 机器人或 Mini App 输入后，奖励立即应用于按时长订阅。没有有效订阅时，后端创建奖励订阅；使用 JSON 套餐目录时采用默认套餐。
- **结账代码：**折扣、时长倍数、流量倍数，或设置 `bonus_requires_payment=true` 的固定天数／GB。代码在付款表单使用；用户在机器人输入时，机器人发送预填代码的 Mini App 按钮。

立即奖励不能用于结账，必须单独激活。结账代码在付款成功前不发放奖励。

<a id="условия-и-ограничения"></a>

## 条件与限制

结账代码可设置最低购买条件：

- `min_subscription_days`：固定天数订单的最短基础购买时长，不含奖励天数。
- `min_subscription_months`：保留的旧月份门槛；按天订单会按兼容转换规则比较，不能把 360 天当作 365 天。
- `min_traffic_gb`：流量购买／加购的最低 GB。

创建付款前校验条件。同一用户对同一码只能激活一次。用户已有使用该码的待付款项时，在付款完成或取消前不能重复使用。总次数由 `max_activations` 控制，有效期由 `valid_until` 控制。

天数与旧月份门槛的兼容判断见 [`PromoEffects.meets_threshold`](../../backend/bot/services/promo_effects.py)；时长单位规则见[上游按天目录](tariffs.md#срок-подписки-в-днях)，不改变独立服务的北京时间月度额度周期。

创建付款时，代码效果、折扣、范围、最低条件、计算金额和承诺发放的固定 GB 保存为付款快照。成功 webhook 使用快照，因此管理员后续停用或修改代码，不改变已有账单的处理条件。激活历史另行保存实际发放的普通与 premium 流量。

<a id="как-влияет-на-подписки-и-трафик"></a>

## 对订阅与流量的影响

- 付款奖励天数在已购时长之外增加。随订阅续费的有效 HWID 加购，其期限也增加奖励天数。
- 固定普通与 premium GB 加入对应可结转余额，下次续费不会丢失。Premium 奖励要求套餐包含 premium 节点组。
- 时长倍数只增加额外天数，不改变付款金额。
- 折扣只改变付款金额，发放天数或 GB 保持基础值。
- 带加购的订阅按整个购物车计算百分比折扣：基础时长价格、设备、普通和 premium 流量，包括立即提高现有限额的按比例补差。先计算小计，再应用折扣，最后使用合作伙伴余额；Telegram Stars 也适用。
- 固定 GB 奖励不改变弹性限额所选档位，单独加入可结转普通／premium 余额，继续按奖励流量规则保留。
- 流量倍数只改变发放 GB，不改变基础付款金额。
- 按流量套餐使用倍数重复购买时，放大后的流量按常规流量包规则加入当前余量。

<a id="персональные-предложения-checkout"></a>

## 个性化结账优惠

扩展可通过 `register_promo_checkout_suggestion_provider` 注册一个或多个个性化代码。这只是推荐入口，不能绕过代码规则：Core 会重新校验启用状态、次数、范围、最低购买条件和支付方式。

Mini App 自动填入第一个推荐代码，用户可移除。Telegram 机器人针对每个订阅时长检查全部推荐，显示有效的最优价格，并允许付款前关闭优惠。单个提供器失败不会中断结账：系统记录日志后继续检查其他来源。

<a id="ссылки-и-совместимость"></a>

## 链接与兼容

后台为每个代码显示两种链接：

- Telegram：`/start promo_<CODE>`。
- 网页应用：带 `startapp=promo_<CODE>` 的链接。

新代码默认转为大写。启用 Remnashop 兼容 `MIGRATION_REMNASHOP_PROMO_CODE_COMPAT_ENABLED` 后，后端先按原始大小写查找，再使用常规规范化，以支持导入的旧代码。

<a id="логи-и-безопасность"></a>

## 日志与安全

失败输入受邮箱／激活码共用的防暴力尝试限流保护。可疑输入可通过 `LOG_SUSPICIOUS_ACTIVITY` 记录；成功的立即激活可通过 `LOG_PROMO_ACTIVATIONS` 记录。
