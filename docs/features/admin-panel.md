# 统一管理后台

<a id="web-管理后台"></a>

<a id="веб-админ-панель"></a>

本页用于查找管理入口和配置参考。日常操作按[管理员操作手册](../user-guide/admin-workflows.md)执行；新接手者先读[接手指南](../handoff.md)。客户与节点是两条主线：一个账号可以拥有多份独立服务，由管理员人工开通，一期不接支付。

具有 `owner` 或 `admin` 角色的账号使用网站同一登录进入管理后台。每个 `/api/admin/*` 请求都会检查有效会话及数据库角色；前端入口或缓存不授予权限。管理员登录不依赖 Telegram。首位所有者初始化与后续角色管理见[不使用 Telegram 运行](telegram-optional.md)。

本页描述源码中的入口及使用约束，不判定某台服务器的部署状态。本地实现、真实执行证据和保留缺口只查[实施计划 §14：本轮本地最终验收](../implementation-plan.md#本轮本地最终验收)，不能据此推定全量生产完成。

## 日常管理入口

<a id="возможности"></a>

下表使用简体中文基础文案与实际路由；“客户”分组内的账号列表菜单仍名为“用户”。部署配置或语言覆盖可能改变显示名称，但不能改变对象含义。

| 分组／入口 | 路由 | 用途 |
| --- | --- | --- |
| 概览 → 运行总览 | `/admin/console-overview` | 查看客户、服务、资源与已确认观测，再进入对应明细。 |
| 客户 → 用户 | `/admin/users` | 找账号、查看独立服务摘要；详情为 `/admin/users/<user_id>`。 |
| 客户 → 全部服务 | `/admin/services` | 跨客户筛选独立服务，进入服务详情、诊断与操作。 |
| 客户 → 套餐模板 | `/admin/service-plans` | 配置资源类型、额度、有效期、价格及后续开通条件。 |
| 客户 → 服务历史 | `/admin/service-history` | 查看删除账号后保留的服务与开通记录，不是活跃客户列表。 |
| 节点 → 节点 | `/admin/nodes` | 查看已纳管节点、关联服务及客户；另设“待接入节点”清单。 |
| 节点 → 节点组与线路 | `/admin/node-resources` | 查看授权组与 Host，预览并处理受支持的资源变更。 |
| 节点 → 专用出口 | `/admin/dedicated-exits` | 登记资源、核验证据、查看占用与人工回收。 |
| 运营 → 服务操作 | `/admin/console-operations` | 按条件查询服务执行记录、历史订单及账号操作记录。 |
| 系统 → 高级维护 | `/admin/advanced-maintenance` | 低频外部面板维护；不代替本项目的日常权益操作。 |

客服、日志、外观、翻译、文档、设置及备份作为通用能力保留。旧销售仪表盘、JSON 单订阅套餐、激活码、礼品和合作伙伴页在独立服务模式下被排除；访问旧 `stats` 入口归到运行总览，其他退役管理页归到套餐模板。残留付款历史或营销入口不表示一期开放购买或奖励业务。兼容资料见[上游参考索引](../upstream/index.md)。

### 节点、影响预览与高级维护

从节点详情查看组、Host、潜在关联服务与去重客户，再进入具体服务排障。授权关联不是实时连接，面板在线身份数也不是客户数。来源缺失、过期或部分可用时保留其提示，不能把未知解释为零；指标说明见[服务器状态与节点指标](server-status.md)。

“待接入节点”只登记名称、地址和备注。保存、修改、删除只操作本地登记，不连接、探测、安装或删除服务器，也不因名称或地址一致自动认领已纳管节点。实际 Node 接入与使用验证是另一个流程。

节点、共享组或 Host 变更先读取影响预览，核对潜在服务、客户、阻断原因及恢复办法。只读预览和重新核对都不执行变更；须使用页面提供的执行入口并确认，之后跟踪操作结果。范围变化或信息不完整时重新核对，不能绕过阻断。详见[资源变更步骤](../user-guide/admin-workflows.md#资源变更)。

高级维护仅使用显式配置且通过校验的 `PANEL_PUBLIC_URL`；未配置或地址无效时页面说明不可用，不回退到 API 地址，不在 URL 中携带凭据，也不承诺外部免登录或 SSO。

## 用户

<a id="пользователи"></a>

从“客户 → 用户”按账号信息搜索，确认内部 ID、邮箱或已绑定身份，再打开详情。账号只计一次，下面的服务按份展示。按账号状态与绑定方式筛选；独立服务模式不使用上游单订阅的 premium 流量筛选来判断客户权益。

日常按以下顺序处理：

- 从客户详情“开通服务”选择套餐模板，核对预检与资源；人工开通不需要付款或申请记录。
- 选择具体服务 ID，查看权益、已确认用量、有效期、交付和同步状态。可重复开通同一模板，每份仍独立。
- 使用该服务的“管理服务”“诊断与操作记录”“查看历史”等入口。账号封禁影响账号下服务，单服务暂停只针对所选服务。
- 查询资源关系、处理交付与计量异常；请求受理后继续看执行结果，不能仅凭按钮成功认定连接已恢复或撤销。
- 需要沟通时进入客服工单；不要把完整订阅、二维码或管理凭据写入公开消息、诊断材料和日志。

模板与服务不是同一对象。模板额度调整按已确认规则影响同模板服务的当前与未来额度，保留已用量；价格、到期和资源条款快照不随模板编辑覆盖。续期不清零用量，不改变原月度锚点。具体步骤见[管理员操作手册](../user-guide/admin-workflows.md)。

### 记录与归档

- 服务内“查看历史”：核对开通与权益变更记录。
- “诊断与操作记录”及全局“服务操作”：跟踪执行阶段、失败、待核对和允许的重试；历史订单不等于已观测远端结果。
- “服务操作”内的账号操作记录：核对账号封禁／解封意图和执行结果，不与单服务操作混计。
- “服务历史”：查询已删除账号的脱离关联记录。删除账号前须完成连接撤销和专用出口人工回收；归档不再授予连接权限。

**通知**标签显示四项用户偏好：邮箱和 Telegram 各自的营销与系统通知。
管理员可修改任意开关；详情页发送的私信、安全消息及支持消息不受这些偏好影响。
私信编辑器可添加**Web App 页面 → 通知设置**按钮，直接打开用户中心对应设置页。

本项目从具体服务取得经过核验的独立订阅，旧账号级订阅及 `/s/` 入口已退役。不要用上游“当前套餐”、普通／premium 两类额度或自动合并面板有效期的语义解释多份服务；账号合并保持服务独立，参见[账号与 Telegram 绑定](telegram-optional.md)和[独立服务交付](../development/service-delivery.md)。

### 本项目套餐模板

从“客户 → 套餐模板”（`/admin/service-plans`）配置多节点订阅或专用 IP 服务，设置流量规则、额度、有效期、价格及资源范围，再到客户详情开通。模板定义与实际服务、开通快照分开；不要编辑 `data/tariffs.json` 来修改已开通的独立服务。具体操作和额度变更边界见[管理员操作手册](../user-guide/admin-workflows.md#套餐与开通)。

## 通用配置参考

以下设置、消息、客服、外观与备份是可复用基础能力。涉及上游单订阅、支付或营销的条目另注明适用范围；配置存在不等于业务已启用。

### 消息按钮中的表情

<a id="эмодзи-в-кнопках-сообщений"></a>

群发、私信和支持回复编辑器中，**表情**按钮位于按钮类型与标题之间。
可选择普通表情或已添加表情集中的图片。所选图标显示在旁边，可替换或删除，
不影响按钮文字、语言版本和目标地址。手机上各字段分行排列，并保持相同高度。

图标会保存在定时群发及其历史中。Telegram 将自定义表情作为原生按钮图标，
普通表情则添加到文字前；Telegram 拒绝时回退为普通字符。
群发和私信的 HTML 邮件通过 CID 嵌入自定义图标，纯文本版本保留 Unicode 字符。
公开支持消息按钮中的受保护图片，仅工单所有者和管理员可见。

### 设置

<a id="настройки"></a>

**系统 → 设置**允许无需编辑 `.env` 修改应用，但仅限 `backend/bot/app/web/admin_settings_manifest.py` 的白名单。即使管理员也不能通过界面任意修改 `Settings` 属性。

修改作为覆盖值保存在数据库中，优先于 `.env` 生效，无需重启。重置后重新使用 `.env` 的值。保存时清除 Web App 公开设置缓存，用户后续请求即可看到变化。

独立服务模式会过滤旧定价、支付、试用、推荐和设备设置分组及部分账号级面板字段。以下列举保留的配置体系，不是当前侧栏逐项清单；是否可编辑以服务端清单与页面显示为准。

- 常规参数：语言、货币、支持链接、文档、必须加入的频道、仅邀请注册模式、Remnawave 凭据和 `/start` 行为。
- Web App 外观与可用性：名称、颜色、标志和 `WEBAPP_ENABLED`。
- 连接指南：`SUBSCRIPTION_GUIDES_ENABLED`、`SUBSCRIPTION_GATEWAY_ENABLED`、`SUBSCRIPTION_GUIDES_BOT_MENU_ENABLED`、读取 Remnawave Panel 配置、JSON 覆盖及备用文件路径。
- 无 JSON 目录时的旧版套餐：订阅周期、RUB/Stars 价格、邀请奖励和流量包。
- 支付渠道：方式开关和排序、下拉列表／独立按钮模式，YooKassa、FreeKassa、Platega、SeverPay、Wata、CryptoPay、Heleket、OxaPay、PayKilla、LAVA、Pally、CloudPayments、Stripe、Tribute 和 Stars 的公开参数及密钥，以及支付方式文字与图标。
- 试用、邀请欢迎奖励、通知、日志、Telegram 防刷、支持、设备区域、设备上限和旧版流量限额。

秘密字段标记为 secret，不应用于任意查看旧值。清单以外的设置仍只能在 `.env` 或代码中修改。

### 支持

<a id="поддержка"></a>

**客服 → 客服**（`/admin/support`）显示来自网站／Mini App 的工单收件列表，支持按状态、优先级、类别和指定管理员筛选，按主题和用户搜索，并按更新时间、创建时间或重要程度排序。

工单详情显示对话、用户上下文及操作：回复用户、内部备注、修改状态／优先级／类别／处理人、关闭工单和跳转用户详情。内部备注不向用户显示。

管理后台导航显示未读工单计数。新工单和用户回复通知通过 `LOG_SUPPORT`、`LOG_SUPPORT_THREAD_ID` 及 `SUPPORT_*` 配置。详情见[用户支持与工单](support.md)。

### 外观

<a id="внешний-вид"></a>

**外观**统一管理品牌和 Web App 主题。标志可通过文件或 HTTPS 链接上传；backend 将文件保存到 `data/webapp-logo/uploads` 并使用本地 URL。未设置时显示项目默认标志。网站图标可从标志生成，也可单独上传。

HTML 邮件使用相同品牌。上传的本地标志作为内嵌图片（`cid:webapp-logo`）加入邮件，邮件客户端无需直接访问 `/webapp-uploaded-logo/...`。公开 HTTPS 链接的标志仍作为外部图片使用。

主题区域读取 `WEBAPP_THEMES_DIR` 目录，显示内置和自定义主题，支持选择当前主题、调整强调色、开启或关闭后台主题，以及分别设置桌面和手机布局的标志缩放。预览按钮打开 `/home?theme_preview=<key>`，保存前不改变全局主题。

`theme.json` 格式、CSS／资源路由和新建主题步骤见[主题文档](webapp-themes.md)。

### 翻译

<a id="переводы"></a>

**系统 → 翻译**可覆盖 `locales/ru.json` 和 `locales/en.json` 中的单个字符串，无需挂载完整本地化文件。字符串按使用位置分组，包括管理后台、Mini App、Telegram 机器人、支付、订阅、支持等。

字符串按受众分为 Mini App／机器人／支付的用户文案，以及管理后台、日志和同步的内部文案。可直接通过语言代码添加其他语言，例如 `uk`、`de` 或 `pt-BR`；这些语言的覆盖值无需独立基础语言文件，缺失字符串从默认语言获取。

`data/locales-overrides.json` 是权威来源，`locale_overrides` 表保存数据库镜像。存在有效 JSON 文件时，backend 和 worker 启动会将数据库完整同步为文件内容，包括删除条目。文件不存在但目录可写时，自动从现有数据库覆盖值创建，或创建空 `{}`。文件未挂载、不可访问或 JSON 暂时损坏时，回退使用数据库。管理后台保存时，将完整最终快照同时写入 JSON 和数据库；若有效 JSON 文件存在却不可覆盖，则拒绝保存，以免数据库与主文件不一致。

文件格式（保留俄语和英语示例值）：

```json
{
  "zh-hans": {
    "menu_personal_account_button": "个人中心"
  },
  "en": {
    "menu_personal_account_button": "Account"
  }
}
```

### 推广伙伴计划

<a id="партнёрская-программа"></a>

**上游兼容参考，独立服务模式不开放此业务页。** 以下历史入口和参数不用于一期人工开通；这里保留财务记录解释及维护参考，不将其列为日常任务。

**推广伙伴**业务页面按所选币种显示汇总指标、申请、档案、客户、佣金、账本、审计和打款。
管理员可批准或拒绝申请、手动创建伙伴、调整比例和状态、轮换链接、将普通被邀请人导入为客户、
调整余额及执行打款。导航计数器每 30 秒更新，显示待处理申请和未结打款。

操作列表分为**伙伴**、**申请**和**打款**标签，各自有独立筛选与排序。
普通被邀请人的批量导入面板仅在普通邀请计划关闭时显示，执行前预览冲突及历史支付，
不会追溯发放佣金。

计划参数不在业务页面重复提供，而位于**系统 → 设置 → 营销计划 → 推广伙伴计划**，
优先于 `.env` 生效且无需重启。即使全局关闭新申请和佣金入账，操作历史仍可访问。
首次启用、客户奖励、财务状态、收款信息加密、核对及回退详见[推广伙伴计划指南](partner-program.md)。

**仅邀请注册**位于**系统 → 设置 → 常规**。开启后，新用户需通过有效的普通邀请、伙伴或未使用的已付费礼品 Telegram/Web App 链接创建账号。礼品链接仅授权注册，领取人仍需登录后单独确认激活。已有 Telegram、WebApp/OAuth、邮箱验证码、免密链接和密码用户无需邀请参数即可继续登录。

保存的设置立即应用于运行进程。应用失败时（例如渠道因错误的环境配置被禁用），后台返回 `not_applied` 列表，并提示“仅在重启后生效”，而非“设置已保存”；此时值已经写入数据库。无法读取环境配置的渠道单独禁用，不影响其他渠道；旧行为曾因一个变量错误导致启动失败，并悄悄阻止所有已保存设置生效。

各渠道的每种支付方式提供 `PAYMENT_<METHOD>_WEBAPP_LABEL_RU`、`PAYMENT_<METHOD>_WEBAPP_LABEL_EN`、`PAYMENT_<METHOD>_WEBAPP_ICON`、`PAYMENT_<METHOD>_TELEGRAM_LABEL_RU`、`PAYMENT_<METHOD>_TELEGRAM_LABEL_EN` 和 `PAYMENT_<METHOD>_TELEGRAM_EMOJI` 显示设置。留空恢复支付渠道模块中的多语言默认值。Web App 图标通过管理后台弹窗从已接入的 Lucide 图标（`frontend/src/lib/components/ui/icons.ts`）中选择。

**支付 → 支付界面**中的 `PAYMENT_METHODS_DISPLAY_MODE` 可选择默认紧凑下拉列表
（`dropdown`）或独立按钮（`buttons`）。金额不足最低要求的方式不会从 Mini App 消失，
而是禁用并提示最低金额。详情见[支付](payments.md#выбор-способа-оплаты-в-mini-app)。

### 上游 JSON 套餐目录

以下是保留的单订阅目录格式及维护说明。独立服务模式不开放旧 `/admin/tariffs` 编辑器，不能将这些标签或支付工具写成当前模板按钮。

**系统 → 套餐**编辑 `TARIFFS_CONFIG_PATH` 文件（默认 `data/tariffs.json`）。保存时 backend 通过 `TariffsConfig` 验证载荷，以 UTF-8 写入 JSON，并清除 Web App 公开数据缓存。

文件尚不存在时，后台打开空目录。保存前至少应有一个启用套餐，且 `default_tariff` 必须引用启用套餐。

套餐编辑器分为以下标签：

- **基本信息**：键及旧键、`period`/`traffic` 模式、可见性、RU/EN 名称和说明、基础 Internal Squads，以及流量套餐的换算比例。
- **价格**：`period` 的周期、价格和邀请奖励；`traffic` 的 GB 套餐包及价格。
- **流量**：基础限额和重置策略、灵活限额的步长／最终最大值／月单价、下单滑块开关；下方是独立的不过期加购包和**“始终允许加购”**（`topup_always_available`）。默认使用达到限额 80% 后出现独立加购。`traffic` 套餐用户重复购买 `traffic_packages` 中的包。
- **高级流量**：高级访问和独立计量、RU/EN 名称、Internal Squads、限额／不限量及重置策略、灵活下单限额、不过期高级加购包和 `premium_topup_always_available`。
- **设备**：基础 HWID 上限、下单滑块的线性单价和设备上限；下方是购买后单独加购的 RUB/Stars 套餐包。

灵活限额与加购包分开配置。普通和高级流量设置 GB 步长、最终最大值、
按目录币种计价的每步月单价，以及可选 ⭐ Stars 单价。设备步长固定为 `1`，
配置额外设备上限和每台设备月单价。参数有效后，才能通过独立开关启用滑块。
完整规则和示例见[下单时加购](tariffs.md#докупки-при-оформлении-подписки)。

标签中的常规设置采用“标题＋说明＋字段或开关”卡片并按逻辑分组。
可拖动的周期和套餐包列表仍使用独立行编辑器。

周期、流量包、普通加购、高级加购及 HWID 套餐包均可拖动排序；顺序保存在 JSON 中，供 Web App 商店和 Telegram 机器人使用。

基础和高级 Internal Squads 通过 `/api/admin/panel/internal-squads` 从 Remnawave 选择。面板不可用时可保存 JSON 中已有的 UUID，但无法加载下拉列表。

启用 Tribute 后，**价格**标签提供**“从 Tribute 获取”**按钮，使用同一 `TRIBUTE_API_KEY` 通过 `/api/admin/tariffs/tribute/catalog` 读取 Creator API 目录。选择订阅会向所有周期填入 `subscription_id` 和 `period_id`；选择 Digital Product 会填入 `product_id` 和商品链接。加载的目录同时与套餐核对，显示价格／币种差异及 Tribute 中已不存在的 ID。仅点击按钮时请求。模式详情见[支付](payments.md#tribute)。

### 实际使用注意事项

<a id="практические-замечания"></a>

下列 `key`、`tariff_key` 和文件挂载说明只针对上游 JSON 目录；独立服务使用数据库模板与服务快照。两类对象不得互换处理。

未迁移有效订阅前，不要修改已发布套餐的 `key`，因为订阅、支付和套餐切换都引用该键。

禁用套餐后它会从商店隐藏，但引用其 `tariff_key` 的有效订阅仍然存在。只有不再有需要从该套餐加购、续订或切换的有效订阅时，删除套餐才安全。

Docker 中应确保容器可写 `TARIFFS_CONFIG_PATH`。例如 `./data` 挂载到 `/app/data` 时，后台可保存 `data/tariffs.json`。

### 上游连接指南配置

以下为上游保留配置说明：**系统 → 设置 → 连接指南**控制内置安装页面。`SUBSCRIPTION_GUIDES_ENABLED` 启用用户中心的 `/install`；`SUBSCRIPTION_GUIDES_BOT_MENU_ENABLED` 让 Telegram 机器人的连接按钮打开 Mini App，而非最终 Remnawave Subscription Page。两者默认开启。

`SUBSCRIPTION_GATEWAY_ENABLED` 允许客户端通过公开链接 `/s/<token>` 导入和更新订阅，默认开启。关闭后指南页面仍可访问，但客户端无法取得配置。新订阅使用哪种链接由 `SUBSCRIPTION_LINK_MODE` 独立决定，默认仍为 `panel`。

Minishop 默认从面板读取 Remnawave Subscription Page 配置（`SUBSCRIPTION_PAGE_CONFIG_PANEL_ENABLED=True`）。这是主要模式，让面板与内置指南使用同一配置。只有显式开启 `SUBSCRIPTION_PAGE_CONFIG_JSON_OVERRIDE_ENABLED`，`SUBSCRIPTION_PAGE_CONFIG_JSON` 才生效；否则虽可保存在后台，但不影响用户。面板配置关闭或不可用时，`SUBSCRIPTION_PAGE_CONFIG_PATH` 仍作为本地 v1 JSON 文件的备用路径。

保存时 backend 按 Remnawave Subscription Page v1 验证 JSON 覆盖值。错误按常规设置校验错误显示；没有可用配置时，用户连接按钮回退到原有最终订阅链接。
