# 套餐与订阅

<a id="тарифы-и-подписки"></a>

订阅通过套餐目录管理，并与 Remnawave Panel 同步。本节介绍可用模式，
并关联目录配置、购买流程和订阅生命周期。

> 本页描述保留的 Minishop 上游套餐和商业流程，不代表本项目当前 MVP 已启用支付、试用、礼品或营销功能。当前目标是一个账号管理多个独立服务、管理员手动激活及无支付。项目独立服务的计量规则见[额度与计量契约](../development/entitlement-metering-contract.md)，不要将本页上游规则当作该契约的替代。

## 订阅模式

<a id="модели-подписок"></a>

- **Period**：按时长订阅，带流量限额和可配置的重置策略。
- **Traffic**：购买不绑定周期的流量包。
- **Premium**：独立高级 squad、计量及重置策略。
- **HWID 设备**：同时使用的基础设备上限，以及临时额外权益。

## 按时长订阅的限额

<a id="лимиты-period-подписки"></a>

普通和高级流量均需区分三个独立层次：

| 层次 | 来源 | 重置方式 |
| --- | --- | --- |
| 套餐基础限额 | `monthly_gb` 或 `premium_monthly_gb` | 按普通或高级计量器的策略重置。 |
| 灵活最终限额 | 用户在购买或续订时通过滑块选择最终值 | 在已付费时间窗口内替代基础限额，按同一策略重置。 |
| 可结转余额 | 独立加购、优惠码固定 GB 奖励或兑换 | 计量器重置时不会重新生成，按对应余额规则用于周期限额之外的消耗。 |

灵活限额不是额外的不过期流量包。例如基础 `100 GB` 时选择 `200 GB`，
表示每个适用重置周期的最终额度为 `200 GB`，而非每月向可结转余额增加 `100 GB`。
`NO_RESET` 时计量器不重置，但每个步长的价格仍按订阅付费月份定义。

普通流量的可结转余额在面板计量器实际重置时结算。
worker 一并保存周期日期、`lifetimeUsedTrafficBytes − usedTrafficBytes` 基准、
周期额度及已确认的超额消耗。因此，设备或灵活限额权益到期，不会把已结束周期的流量
误转为付费流量包消耗。周期内降低额度时保留已提供服务的部分；
到期权益未使用的部分不结转。提高额度不会返还此前已确认的流量包消耗。

连续重置时，从余额扣除已结束周期超过其额度的消耗。
面板迟到响应不会破坏该计算，重复响应不会再次扣流量。
未用流量包继续结转；耗尽后仅剩周期额度。普通和高级流量使用同一超额消耗算法；
高级流量按所选节点统计，在当前周期限额中保留已扣部分，普通流量包则按面板计数结算。

漏掉多次重置时，只有面板 UTC 日历史总和与 lifetime 计数变化完全一致，worker 才使用该历史。
每个周期有自己的额度，相邻周期未用额度不能覆盖本周期消耗。
历史周期内权益发生变化时，采用该周期保守的额度上界，因为日统计无法确定每个字节
发生在权益变化前还是之后。

历史缺失、因保留期被截断，或重置边界位于 UTC 日内时，只扣除 worker 此前可靠确认的消耗。
不会从累计计数猜测恢复未知消耗。缺少 lifetime 计数时完整保留计量快照，
不以通知日期替代基准日期。绑定新的面板用户或其 lifetime 计数重启时，
开始新的观测，不扣除旧消耗。无限量模式不会产生新的付费流量包消耗。

升级后，首个可信面板响应开始当前周期观测，不追溯扣除此前已结束周期。
迁移 `0098_topup_period_lifetime` 和 `0099_regular_topup_accounting`
添加计量基准及额度快照，不修改现有迁移。

## 生命周期

<a id="жизненный-цикл"></a>

邀请时长奖励适用于用户本人付费的 period 订阅，个人余额付款也计入。
充值、购买礼品、流量购买和零价个人操作不占用首次购买资格。
开启 `REFERRAL_GIFT_ACTIVATION_ENABLED` 后，领取人成功激活礼品也按其已有邀请关系计入。
启用 `REFERRAL_ONE_BONUS_PER_REFEREE` 时，首次事件为个人购买或符合条件的礼品激活之一；
第二种事件不再为双方增加时长。关闭礼品选项不会抹去已计入的激活。
判定后的退款不重置该事实，也不撤销已增加时长。详情见[礼品规则](gifts.md#реферальное-начисление)。

付款成功时，为每个参与者分别保存待履行权益。worker 独立交付，
面板失败时延迟重试，等待最长一小时。保存的绝对到期时间和本地预留防止超时或下一次购买
导致重复或遗漏发放。已应用部分不会重做。面板确认前付款仍保持成功，交付后才发送奖励通知。
迁移不会重放无法可靠还原部分交付状态的历史付款。
队列的 `state`、`attempts`、`next_attempt_at`、`last_error` 可用于诊断交付延迟；
标准 worker 必须运行。

通常 Minishop 创建面板用户，应用试用或首次购买，同步状态，并处理续订、加购和套餐切换。
提前续订同一套餐时，新时长全额计费；提高限额或设备数的部分按当前剩余窗口比例计费。
降级不退款，从下一订阅边界开始生效。

购买另一套餐的周期不会隐式切换当前有效套餐：backend 返回 `tariff_switch_required`，
应使用独立切换流程。完整规则见[自动续订、试用和奖励](tariffs.md#автопродление-пробный-период-и-бонусы)
及[套餐切换](tariffs.md#смена-тарифа)。

## 重新签发访问凭据

<a id="перевыпуск-доступа"></a>

用户按钮由 `SUBSCRIPTION_REISSUE_ENABLED=true` 开启，默认关闭。
邮箱非必需，新链接通过可用的邮箱或 Telegram 渠道发送，并保留在 Mini App 中。

Mini App 和管理后台共用同一持久化重签发操作。并发请求返回 `409` 和 `Retry-After`；
完成后短时间内重试返回同一链接。请求面板前先撤销旧公开访问授权。
如果面板已更换标识但响应丢失，重试核对当前标识，完成已保存操作，不再重复更换。
面板拒绝返回 `502`；旧授权保持撤销，操作可通过重试恢复。

## 升级为按天周期

<a id="обновление-на-дневные-периоды"></a>

升级前保存数据库和套餐目录。backend、worker 和 frontend 应同步升级，切换期间停止创建新付款。
迁移添加按天字段，保留旧按月字段、访问日期、支付金额和奖励。
旧账单及外部周期订阅继续遵循原日历条件。
新的一次性购买及本地自动续订增加精确 UTC 天数。

优惠码门槛按基础已付费时长比较，不含奖励：360 天不满足 365 天门槛。
倍数奖励天数计算为 `bonus_days + ROUND_HALF_UP(duration_days * (multiplier - 1))`；
旧的已固定日历订单保留原计算方式。一天期购买不会立即触发提前多天的到期提醒，
短时小时提醒仍按设置工作。

产生按天付款后，只能回退到支持按天字段及新快照的版本。
不要启动旧 worker，也不要用旧数据库覆盖新的财务操作。
目录及支付方式限制见[套餐](tariffs.md)。
